# Kilacraft-AI - 数据库与持久化配置指南

> **最后更新**: 2026-05-06  
> **说明**: 本文档详细介绍 Kilacraft-AI 的数据库架构、持久化内容、配置方法和数据管理

---

## 📖 概述

v2.0.0 起 Kilacraft-AI 引入数据库持久化层，玩家对话、画像、社交关系等重要数据重启不丢失。同时支持 H2 嵌入式数据库和 MySQL 外挂数据库，可根据服务器规模和需求灵活选择。

### 核心特性

- ✅ **双数据库支持**：同时支持 H2 嵌入式数据库（零配置、单服友好）和 MySQL（多子服数据共享）
- ✅ **热切换数据库**：通过 `/kilacraft reload` 即可在 H2 和 MySQL 间切换，失败自动回退
- ✅ **自动建表**：首次启动自动创建所有表结构（H2/MySQL 双方言兼容）
- ✅ **HikariCP 连接池**：高性能数据库连接池
- ✅ **异步写入**：所有写入操作异步执行，不阻塞主线程
- ✅ **定时清理**：过期数据可配置保留天数，自动清理

---

## 🚀 快速开始

### 选择数据库类型

Kilacraft-AI 同时支持两种数据库，根据你的服务器规模选择：

**H2 嵌入式数据库**（适合单服 / 开发测试）：  
零配置，开箱即用。首次启动自动在 `plugins/Kilacraft-AI/data/` 目录创建数据库文件，无需安装任何外部服务。

**MySQL 外挂数据库**（适合多子服 / 生产环境）：  
多子服间共享玩家数据。编辑 `plugins/Kilacraft-AI/database.yml`：

```yaml
database:
  type: mysql
  host: localhost
  port: 3306
  database: kilacraft
  username: root
  password: your-password
  table_prefix: "kca_"            # 表名前缀
  data_retention_days: 30         # 数据保留天数
```

配置完成后执行 `/kilacraft reload` 即可热切换，失败自动回退旧连接池。

## 🗄️ 数据表结构

### kca_conversation - 对话历史

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，自增 |
| `player_uuid` | VARCHAR(36) | 玩家 UUID |
| `player_name` | VARCHAR(64) | 玩家名称 |
| `role` | VARCHAR(16) | 角色（user/assistant） |
| `message` | TEXT | 消息内容 |
| `source` | VARCHAR(32) | 来源标识（chat/command/console_plugin/console/greeting/afk_callback） |
| `created_at` | TIMESTAMP | 创建时间 |

**写入策略**：Write-Behind 异步刷盘  
**刷盘频率**：每 30 秒，或消息队列 ≥20 条时立即刷盘  
**读取策略**：玩家首次发言时懒加载最近 N 条历史

### kca_player_profile - 玩家画像

| 字段 | 类型 | 说明 |
|------|------|------|
| `player_uuid` | VARCHAR(36) | 玩家 UUID（唯一） |
| `player_name` | VARCHAR(64) | 玩家名称 |
| `first_login` | TIMESTAMP | 首次登录时间 |
| `total_playtime_seconds` | BIGINT | 累计在线时长（秒） |
| `login_count` | INT | 登录次数 |
| `profile_data` | TEXT | 画像 JSON（五点维度） |
| `last_analysis_time` | TIMESTAMP | 上次画像分析时间 |
| `version_stamp` | BIGINT | 版本戳（防竞态） |

**画像维度**：
- 游戏风格：PVP/PVE/建筑/探索/红石/生存等
- 性格特征：外向/内向/冒险/谨慎等
- 内容偏好：经济/战斗/社交/建造等
- 沟通风格：简洁/详细/幽默/正式等
- 特别观察：LLM 自由发挥的个性化观察

**分析触发条件**（三重门控，三者同时满足才触发）：
1. 距上次分析 ≥ 可配置时间间隔
2. 累计消息数 ≥ 阈值
3. 滑动窗口内有足够新消息

### kca_server_event - 服务器事件

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，自增 |
| `player_uuid` | VARCHAR(36) | 相关玩家 UUID |
| `target_uuid` | VARCHAR(36) | 目标玩家 UUID（可为空） |
| `event_type` | VARCHAR(64) | 事件类型 |
| `data` | TEXT | 事件数据（事件特定的结构化文本） |
| `created_at` | TIMESTAMP | 事件时间 |

**事件类型**：`PLAYER_DEATH`、`PLAYER_ADVANCEMENT`、`PLAYER_LEVEL_UP`、`MARKET_ITEM_SOLD`、`MARKET_ITEM_LISTED`、`MARKET_MONEY_RECEIVED`、`PLAYER_LOGIN`、`PLAYER_LOGOUT`、`PLAYER_FIRST_JOIN` 等

> **注意**：该表不存储 `player_name` 字段。当需要显示玩家名时（如 AI 问候中的好友动态），通过 LEFT JOIN `kca_player_profile` 表获取。此设计避免名称变更导致的数据不一致。

### kca_social_relation - 社交关系

| 字段 | 类型 | 说明 |
|------|------|------|
| `player_uuid` | VARCHAR(36) | 玩家 UUID |
| `target_uuid` | VARCHAR(36) | 目标玩家 UUID |
| `strength` | DOUBLE | 关系强度 |
| `last_interaction` | TIMESTAMP | 最后交互时间 |

**交互权重**：
- 私聊：+0.01
- TPA 传送：+0.02
- Skill 交互（白名单 Skill）：+0.005

**衰减机制**：每日衰减 5%，强度低于阈值自动清理。

### kca_skill_log - 技能审计日志

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BIGINT | 主键，自增 |
| `player_uuid` | VARCHAR(36) | 玩家 UUID |
| `player_name` | VARCHAR(64) | 玩家名称 |
| `skill_name` | VARCHAR(128) | 技能名称 |
| `action` | VARCHAR(128) | 动作名称 |
| `parameters` | TEXT | 参数 JSON |
| `result` | VARCHAR(32) | 执行结果（SUCCESS/FAILURE/TIMEOUT） |
| `duration_ms` | BIGINT | 执行耗时（毫秒） |
| `trigger_source` | VARCHAR(64) | 触发来源 |
| `created_at` | TIMESTAMP | 创建时间 |

### kca_watermark - 水位标记（分布式互斥）

| 字段 | 类型 | 说明 |
|------|------|------|
| `task_name` | VARCHAR(128) | 任务名称（唯一） |
| `last_run_date` | VARCHAR(16) | 上次运行日期 |
| `server_id` | VARCHAR(64) | 执行服务器标识 |
| `updated_at` | TIMESTAMP | 更新时间 |

用于社交关系衰减等每日任务的分布式互斥（`SELECT FOR UPDATE` 行锁）。

## ⚙️ 配置参考

### database.yml 完整配置

```yaml
database:
  # 数据库类型：h2（嵌入式，默认）或 mysql（外挂）
  type: h2

  # H2 配置（type=h2 时使用）
  h2:
    file_path: "data/kilacraft"   # 数据库文件路径（相对于插件目录）

  # MySQL 配置（type=mysql 时使用）
  mysql:
    host: localhost
    port: 3306
    database: kilacraft
    username: root
    password: ""
    properties:
      useSSL: false
      allowPublicKeyRetrieval: true
      serverTimezone: Asia/Shanghai

  # HikariCP 连接池配置
  pool:
    maximum_pool_size: 10
    minimum_idle: 2
    connection_timeout: 30000
    idle_timeout: 600000
    max_lifetime: 1800000

  # 表名前缀
  table_prefix: "kca_"

  # 数据保留天数（超过此天数的对话记录将被清理）
  data_retention_days: 30

  # 清理任务执行间隔（小时）
  cleanup_interval_hours: 24
```

## 🔧 操作指南

### 备份数据库

**H2 模式**：
直接备份 `plugins/Kilacraft-AI/data/` 目录下的 `.mv.db` 文件。

**MySQL 模式**：
使用 mysqldump 或你常用的数据库备份方案。

### 从 H2 迁移到 MySQL

1. 备份 `plugins/Kilacraft-AI/` 目录
2. 手动导出 H2 数据
3. 修改 `database.yml` 中的 `type` 为 `mysql`
4. 执行 `/kilacraft reload` 使新配置生效

### 切换回 H2

1. 修改 `database.yml` 的 `type` 回 `h2`
2. 执行 `/kilacraft reload`
3. 如切换失败，插件自动回退到旧连接池

## 🐛 常见问题

**Q: H2 数据库文件在哪里？**  
`plugins/Kilacraft-AI/data/kilacraft.mv.db`

**Q: 如何重置所有数据？**  
停止服务器，删除 `plugins/Kilacraft-AI/data/` 目录，重启即可。

**Q: MySQL 连接失败怎么办？**  
检查 `database.yml` 中的连接参数是否正确，MySQL 服务是否运行。切换失败时插件自动回退到旧连接池，不会丢失数据。

**Q: 清理间隔如何配置？**  
修改 `database.yml` 中的 `cleanup_interval_hours` 和 `data_retention_days`，执行 `/kilacraft reload` 生效。
