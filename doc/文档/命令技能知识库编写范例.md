# 让 AI 执行自定义命令（commandSkill）—— 知识库编写范例

> **最后更新**: 2026-08-01  
> **说明**: 服主在知识库中编写服务器自定义命令的说明，让 AI 通过命令技能（CommandSkill）代为执行。配合两阶段意图识别 + 语料播种词典使用。

---

## 适用场景

服务器装了一批**自定义命令插件**（Essentials、CMI、HuskTowns、MyHome 等），提供 `/back`、`/home`、`/spawn`、`/tpa`、`/menu` 等命令。希望玩家用自然语言（"回家""送我到 Steve 那"）就能让 AI 代为执行——把这些命令写进知识库即可。

前提：在 `config.yml` 中开启 `command_skill.enabled: true`。

---

## 工作链路

```
玩家说话（"我死了想回去捡东西"）
   ↓
Phase1 意图粗选（不查知识库）
   ↓
Phase2 意图精选【检索知识库】← 命中 "/back 返回死亡点捡回物品" 片段
   ↓
LLM 决定：skill=command, action=execute_command, command="back"
   ↓
命令技能（CommandSkill）以玩家身份执行 /back
```

三个关键认知：

1. **知识库在 Phase2 意图识别时被检索**，不是命令技能执行时。知识库的作用是"教 Phase2 的 LLM 理解你的命令、生成正确的 `command` 参数"。
2. **命令技能是兜底技能**：有专用技能（经济转账、市场查询等）能完成的需求，专用技能优先；只有专用技能覆盖不到的服务器自定义命令，才靠命令技能 + 知识库。
3. **`command` 参数不含 `/`**：LLM 要填 `back`，不是 `/back`。

---

## 命令技能（CommandSkill）契约

| 项 | 值 |
|---|---|
| 技能名 | `command`（实现类 `CommandSkill`） |
| 动作 | `execute_command` |
| 参数 | `command`：完整命令，**不含前导 `/`**，从玩家消息中提取 |
| 权限 | `kilacraft.command.execute`（默认 OP）；以玩家本人身份执行，受玩家自身权限约束（玩家没有的权限 AI 也没有） |
| 开关 | 需在 `config.yml` 开启 `command_skill.enabled: true` 才会注册 |
| 定位 | 兜底技能（有专用技能优先使用） |

---

## 完整范例（复制到 `knowledge/自定义命令.md`，替换为你的真实命令）

````markdown
# 服务器自定义命令清单

玩家用自然语言提出需求时，AI 可以代为执行下面的命令。命令以玩家本人身份执行，玩家没有的权限 AI 同样没有。

## 回到死亡点 / 返回刚才位置（/back）
`/back` 让你回到上一次所在的位置——通常是死亡掉落物品的地方，也可能是上次传送前的位置。冷却 30 秒，战斗状态下不能使用。
Q: 我死了怎么回去捡东西 / 刚才掉的东西还能拿回来吗 / 送我回刚才那 / back 冷却多久
AI 执行：back

## 回到自己的家（/home）
`/home` 直接传送回你设置的家。设了多个家时可在后面加家名，例如 `/home 主基地` 去名叫"主基地"的家。
Q: 回家 / 回我的基地 / 送我回小屋 / 去我那个叫主基地的家
AI 执行：home（带家名时如 home 主基地）

## 传送到其他玩家身边（/tpa）
`/tpa 玩家名` 向对方发送传送请求，对方同意后才能过去，不能强制传送。例如 `/tpa Steve` 请求传送到 Steve。
Q: 传送到Steve / 我想去找我朋友 / 送我到Alex旁边 / 帮我传给Tom
AI 执行：tpa 玩家名（如 tpa Steve）

## 回主城 / 出生点（/spawn）
`/spawn` 传送回服务器主城出生点，不需要任何参数。
Q: 回主城 / 去出生点 / 怎么回新手村 / 传送回城里
AI 执行：spawn

## 打开服务器菜单（/menu）
`/menu` 打开综合菜单，里面包含商店、传送、任务、礼包等所有功能入口。
Q: 打开菜单 / 商店在哪 / 我要买东西 / 怎么领礼包 / 任务在哪看
AI 执行：menu
````

## 设计要点（每处写法服务链路的哪一环）

| 写法 | 服务哪一环 | 为什么 |
|---|---|---|
| 命令名一律写 `/back` 全称（标题+正文都出现） | 语料播种 + 关键词加权 | `/back` 触发**语料播种**（`back` 自动进 HanLP 词典，玩家直接说 `/back` 时不被切碎）；同时是 ≥4 字符长词，BM25 权重 ×3 |
| 标题堆中文同义词（回家/返回/死亡点/主城/出生点） | **中文召回主力** | 玩家用中文说"回家"命中标题"回家"→ 标题词加权 `+15×词权重`。这是语料播种管不到的部分，召回最依赖它 |
| 标题与正文之间**无空行** | 标题块完整 | 空行会切断标题块，正文变成无标题孤立片段，丢失标题加权（还可能 <20 字符被丢弃） |
| 每条 `Q:` 列 2~4 种玩家问法 | 补关键词覆盖 | 把玩家会用、但正文没写过的词（"捡东西""新手村"）铺进文档；短问法的关键词串还可能整体命中 +50 |
| `AI 执行：back` 这一行 | 教 LLM 填 command | 明确告诉 Phase2 的 LLM `command` 该填什么、**不含 `/`**，减少误填成 `/back` 或参数格式错误 |
| 一个命令一个 `##` 块 | 召回完整性 | BM25 按标题分段，检索"回家"时召回的是完整一块（命令+作用+问法），LLM 拿到生成 command 所需的全部信息 |
| 每段 20~500 字符 | 不被丢弃/不丢加权 | <20 字符片段被过滤；>500 字符会被二次切分，第二段起丢失标题加权 |
| 只写服务器自定义命令，不写"给钱/查市场" | 命令技能兜底定位 | 有专用技能（经济/市场）的需求由专用技能处理，写进这里反而干扰命中 |

---

## 两个特别提醒

1. **中文召回才是大头**：语料播种词典只在玩家输入含英文命令词（`/back`、`ender-dragon`）时帮忙；绝大多数玩家用中文说"回家/回主城"，靠的是**标题和正文里的中文同义词覆盖**。同义词堆得越全，召回越稳——这是最该花精力的地方。

2. **带参数的命令务必给示例**：像 `/home 主基地`、`/tpa Steve` 这种，光写"传送到玩家"LLM 容易填错；给一个具体示例（`AI 执行：tpa Steve`），LLM 会照着格式填参数。

---

## 检查清单

优化任何命令技能知识库文件时逐条对照：

- ☐ 每个命令一个 `##` 标题，标题含【中文说法 + 命令名】（如 `回家 / 返回（/home）`）？
- ☐ 命令名写 `/全称`（触发语料播种 + 长词加权）？
- ☐ 标题与正文之间没有空行？
- ☐ 每段 20~500 字符？
- ☐ 每个命令配了 `Q:` 列玩家可能的多种问法？
- ☐ 每个命令有 `AI 执行：xxx` 明确 command 值（不含 `/`）？
- ☐ 带参数的命令给了具体示例？
- ☐ 没有把专用技能覆盖的需求（经济/市场）写进来？
- ☐ 文件用 UTF-8 编码、`.md` 扩展名，放在 `knowledge/` 目录？
