# 让 AI 执行自定义命令（commandSkill）—— 命令文档编写范例

> **最后更新**: 2026-08-04  
> **说明**: 服主在 `commands/commands.md` 中登记服务器命令，让 AI 通过命令技能（CommandSkill）代为执行。本机制独立于知识库（`knowledge/` 目录）。

---

## 适用场景

服务器装了一批**自定义命令插件**（Essentials、CMI、HuskTowns、MyHome 等），提供 `/back`、`/home`、`/spawn`、`/tpa`、`/menu` 等命令。希望玩家用自然语言（"回家""送我到 Steve 那"）就能让 AI 代为执行——把这些命令登记进 `commands/commands.md` 即可。

> ⚠️ **重要变更**：早期版本把命令写进知识库（`knowledge/` 目录）靠 BM25 检索，该机制已废弃。命令现在走**独立的命令文档**（`commands/commands.md`），**不参与知识库检索**，也不再需要往 HanLP 词典"播种"。命令技能始终注册，无需在 `config.yml` 里开关。

---

## 工作链路

```
玩家说话（"我死了想回去捡东西"）
   ↓
CommandSkill 作为 DynamicContextProvider，按玩家权限过滤出可见命令，
   注入到 Phase1 提示词的"AI 可执行命令"摘要里
   ↓
LLM 看到"back：返回死亡点"等条目，决定 skill=command, command="back"
   ↓
CommandSkill 以玩家身份执行 /back（受玩家自身权限约束）
```

三个关键认知：

1. **命令文档独立于知识库**：命令条目解析自 `commands/commands.md`，不走知识库的分段/检索/评分流程，也不参与语料播种（HanLP 词典只扫 `knowledge/`，不扫 `commands/`）。
2. **命令技能是兜底技能**：有专用技能（经济转账、市场查询等）能完成的需求，专用技能优先；只有专用技能覆盖不到的服务器自定义命令，才靠命令技能 + 命令文档。
3. **`command` 参数不含 `/`**：LLM 要填 `back`，不是 `/back`。文档里的示例字段会引导它正确填值。

---

## 命令技能（CommandSkill）契约

| 项 | 值 |
|---|---|
| 技能名 | `command`（实现类 `CommandSkill`，同时实现 `DynamicContextProvider` 与 `CallerDescriptionProvider`） |
| 动作 | 以玩家身份执行命令 |
| 参数 | `command`：完整命令，**不含前导 `/`**，从玩家消息中提取 |
| 权限 | `kilacraft.command.execute`（默认 OP）；以玩家本人身份执行，受玩家自身权限约束（玩家没有的权限 AI 也没有） |
| 命令来源 | `commands/commands.md`（中文/默认）、`commands/<lang>/commands.md`（按客户端语言匹配，如 `commands/en/commands.md`） |
| 开关 | **无需开关**，命令技能始终注册（旧的 `command_skill.enabled` 配置项已移除） |
| 定位 | 兜底技能（有专用技能优先使用） |

## 命令文档格式

文件位置（在插件数据文件夹下）：

```
plugins/Kilacraft-AI/
├── commands/
│   ├── commands.md          # 默认/中文命令文档
│   └── en/
│       └── commands.md      # 英文客户端使用的命令文档
└── knowledge/               # 知识库（与本机制无关）
```

> 插件首次启动时会自动生成 `commands/commands.md`，里面已内置 Kilacraft-AI 自身的命令，并附带格式说明和注释示例。直接在文件末尾追加你服务器的命令即可。

每条命令用一个 `##` 标题声明（**不含前导 `/`**），紧跟四个字段：

```
## 命令名
说明: 一句话描述命令的作用
示例: 命令的完整调用示例（含参数）
权限: 执行该命令所需的服务器权限节点
关键词: 玩家可能用来表达这个意图的词语，逗号分隔（可选）
```

**字段含义**：

| 字段 | 必填 | 作用 |
|---|---|---|
| `说明:` | 是 | 一句话描述命令作用，注入提示词后供 LLM 判断该命令是否匹配玩家意图 |
| `示例:` | 是 | 完整调用示例（含参数），引导 LLM 填出正确的 `command` 值（**不含 `/`**） |
| `权限:` | 是 | 服务端权限节点。CommandSkill 会**按玩家权限实时过滤**：玩家没有该权限的命令不会注入到该玩家的提示词里（AI 也看不到、更不会尝试执行） |
| `关键词:` | 否 | 玩家可能用来表达这个意图的词，逗号分隔。补充同义词/口语说法，提高识别准确率 |

> 命令名也可以带参数占位符，如 `## kila clear <玩家名>`、`## home [家名]`，方便描述带参数的命令。

## 完整范例（直接编辑 `commands/commands.md`，在文件末尾追加）

下面展示如何在内置命令之后追加第三方插件命令。前半部分是插件自带的 `kila` 系列命令（已内置，**无需手写**，这里仅作格式参考）；后半部分是你要补充的 Essentials 等第三方命令。

````markdown
# AI 可执行命令文档
#
# 本文件由 Kilacraft-AI 自动生成，已内置插件自身的命令。
# 请在此补充服务器上其他插件的命令和自定义命令。
# 修改后执行 /kila reload 即可生效。
#
# 本文件独立于知识库（knowledge/ 目录），仅用于 AI 命令执行技能的命令识别。

# ...（此处省略插件内置的 kila clear / kila usage / kila reload 等命令）...

# ============ 以上为内置命令，以下请自行补充 ============

## home
说明: 回到已设置的家
示例: home [家名]
权限: essentials.home
关键词: 回家, 回基地, 回小屋, 去我那个家

## tpa
说明: 请求传送到指定玩家身边（对方同意后才能过去）
示例: tpa 玩家名
权限: essentials.tpa
关键词: 传送, 找玩家, 去找朋友, 送到某人旁边

## back
说明: 回到上一次所在的位置（通常是死亡掉落物品的地方）
示例: back
权限: essentials.back
关键词: 回死亡点, 捡回东西, 送我回刚才那

## spawn
说明: 传送回服务器主城出生点
示例: spawn
权限: essentials.spawn
关键词: 回主城, 去出生点, 回新手村, 传送回城里

## menu
说明: 打开综合菜单（含商店、传送、任务、礼包等入口）
示例: menu
权限: essentials.menu
关键词: 打开菜单, 商店在哪, 领礼包, 任务在哪看
````

> 英文客户端会读 `commands/en/commands.md`，格式完全相同，只是字段名换成 `description:` / `example:` / `permission:` / `keywords:`（见插件生成的英文模板）。

## 设计要点（每处写法服务链路的哪一环）

| 写法 | 服务哪一环 | 为什么 |
|---|---|---|
| 命令名作为 `##` 标题，**不带 `/`** | 解析 + 提示词注入 | 解析器按 `##` 切分命令条目；标题就是命令名本身，注入后 LLM 直接看到可填的 `command` 值 |
| `示例:` 字段给完整调用（含参数） | 教 LLM 填 command | 明确告诉 LLM 该填什么、**不含 `/`**；带参数的命令（如 `tpa 玩家名`）靠示例示范参数格式，减少误填 |
| `权限:` 字段填准服务端权限节点 | **按玩家权限动态过滤** | CommandSkill 实现了 `DynamicContextProvider`，会拿玩家当前权限逐条过滤：玩家没有 `essentials.home` 就不会把 `home` 注入给 AI，AI 既看不到也不会尝试执行（杜绝无权命令被执行） |
| `关键词:` 堆中文同义词/口语 | 提高识别准确率 | 玩家用中文说"回家/回主城"时，靠这些词让 LLM 匹配到正确的命令条目 |
| `说明:` 写清命令边界与限制 | 减少 LLM 误用 | 一句话说清"能做什么/什么时候用不了"（如"对方同意后才能过去"），避免 AI 在不适用场景硬塞命令 |
| 只写服务器自定义命令，不写"给钱/查市场" | 命令技能兜底定位 | 有专用技能（经济/市场）的需求由专用技能处理，写进这里反而干扰命中 |
| 一个命令一个 `##` 块 | 召回完整性 | 每条命令作为独立条目注入，LLM 拿到生成 command 所需的全部信息（说明+示例+关键词） |

## 两个特别提醒

1. **命令文档不进 HanLP 词典**：语料播种（词典自动补充）只扫 `knowledge/` 目录，**不扫 `commands/`**。所以命令文档里写不写 `/back` 全称都不会影响分词。命令识别靠的是上面的结构化字段 + 提示词，不是关键词分词召回——这和旧机制不同。

2. **带参数的命令务必给示例**：像 `home 主基地`、`tpa Steve` 这种，光写"传送到玩家"LLM 容易填错；给一个具体示例（`示例: tpa 玩家名`），LLM 会照着格式填参数。

## 运维操作

| 操作 | 命令 | 作用 |
|---|---|---|
| 重新加载命令文档 | `/kila reload` | 编辑 `commands/commands.md` 后执行，立即生效（无需重启服务器） |
| 命令文档健康检查 | `/kila doctor` | 自检时会检查命令技能的命令条目（`hasCommandEntries`），若文档为空或格式有误会提示 |

> 命令文档的修改是**热更新**：改完 `/kila reload` 即可，不用重启。换语言版本（中/英）也是读文件时按客户端语言选择，无需额外配置。

## 检查清单

优化任何命令文档时逐条对照：

- ☐ 每个命令一个 `##` 标题，**标题不带前导 `/`**？
- ☐ 每条命令都有 `说明:` / `示例:` / `权限:` 三个必填字段？
- ☐ `权限:` 填的是**准确的服务端权限节点**（如 `essentials.home`）？
- ☐ `示例:` 给的是完整调用且**不含 `/`**（如 `home [家名]`，不是 `/home`）？
- ☐ 带参数的命令在 `示例:` 里给了具体参数占位（如 `tpa 玩家名`）？
- ☐ `关键词:` 列了玩家可能的多种中文/口语说法？
- ☐ 没有把专用技能覆盖的需求（经济/市场）写进来？
- ☐ 文件放在 `commands/commands.md`（英文放 `commands/en/commands.md`），UTF-8 编码？
- ☐ 改完后执行了 `/kila reload`，并用 `/kila doctor` 自检通过？
