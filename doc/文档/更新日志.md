## v2.0.0 - 数据库持久化与对话历史保存、玩家画像与社交关系、AI 登录问候、配置架构重构、8 种新挂机任务、全球市场操作技能、通用工具技能、Embedding 语义检索、挂机任务智能回调

### ✨ 新增功能
- **8 种全新挂机任务类型**：挂机任务从 12 种扩展至 20 种，覆盖更多游戏场景
  - **监视玩家钓鱼**：监视自己的钓鱼活动，钓到鱼时自动通知或触发后续动作
    - 示例：“钓到鱼了告诉我并查市场价格”
  - **监视玩家聊天**：监视自己发送的聊天消息，可用于暗号触发自动化流程
    - 示例：“我说'开始刷怪'的时候帮我执行刷怪塔开关命令”
  - **监视方块破坏**：监视自己破坏方块，挖到指定矿物时触发后续动作
    - 示例：“我挖到钻石了告诉我背包里有多少钻石”
  - **监视实体死亡**：监视附近的实体死亡，可用于 BOSS 击杀检测
    - 示例：“凋灵死了告诉我”
  - **监视实体生成**：监视附近的实体生成，可用于刷怪塔效率监控
    - 示例：“刷怪塔生成僵尸村民了告诉我”
  - **监视实体爆炸**：监视附近的爆炸事件，可用于防炸服预警
    - 示例：“有爆炸的时候告诉我坐标”
  - **监视熔炉烧炼**：监视熔炉烧炼完成，当炉内物品全部烧完时通知
    - 示例：“熔炉烧完了告诉我”
  - **监视作物生长**：监视作物成熟，可用于自动化农场管理
    - 示例：“小麦熟了告诉我并查市场价格”
  - 所有新任务类型均支持纯通知和回调双模式
- **全球市场操作技能（MarketActionSkill）**：全新技能，支持 AI 代玩家执行全球市场交易操作
  - 独立于原有的 MarketQuerySkill（只读查询），提供写入类市场操作能力
  - 仅当 GlobalMarketPlus 插件存在时自动注册
  - 支持 9 种市场操作：
    - **搜索商品**（search_item）：搜索并打开购买 GUI
    - **上架物品**（sell_item）：将手中物品上架，支持引导式价格确认
    - **领取邮箱**（pickup_mail）：一键领取所有或指定邮件
    - **发起求购**（buy_item）：以指定单价发起收购订单
    - **下架商品**（cancel_listing）：展示在售列表，选择后下架
    - **转账**（transfer_money）：向其他玩家转账，大额需二次确认
    - **发起拍卖**（auction_item）：将手中物品发起拍卖
    - **批量出售**（sell_inventory）：将背包内所有同类物品批量上架
    - **批量收购**（buy_inventory）：以指定单价发起批量收购订单
  - 所有写操作通过 Bukkit 命令代执行，由 GlobalMarketPlus 插件内部保证原子性
- **UtilitySkill（通用工具技能）**：新增 utility 技能，提供三个基础动作，可在多步骤任务中灵活编排
  - **delay_wait**：非阻塞延迟 1-60 秒，使用专用调度器，不占用 I/O 线程池
    - 示例："先等 10 秒，然后再帮我查一下市场价格"
  - **notify_player**：将阶段性结果通过独立 LLM 调用概括后主动通知玩家，支持超时保护，尊重服主流式输出配置
    - 示例："先帮我查余额和背包，总结完后告诉我结果，然后再上架钻石"
  - **broadcast_message**：OP 管理员专用，将消息通过 AI 美化后全服广播（CHAT 载体），支持单意图和多步骤编排
    - 示例："帮我写一段公告：本周末全服双倍经验"
    - 可结合多步骤任务编排："先查一下在线玩家列表，然后帮我广播一条活动通知"
- **知识库 Embedding 语义检索**：通过调用 Embedding API 获取文本向量，用余弦相似度替代 BM25 算法进行语义检索
  - 支持配置不同 Embedding 供应商（如智谱AI、硅基流动、OpenAI 等），可与 LLM 供应商不同
  - 向量缓存持久化，避免每次启动重新计算
  - 可配置最低相似度阈值、向量维度、API 超时等参数
  - 未配置时自动降级回原有 BM25 算法检索
- **数据库持久化层**：同时支持 H2 嵌入式数据库（零配置开箱即用）和 MySQL 外挂数据库（多子服共享数据）
  - HikariCP 连接池，支持 `/kilacraft reload` 热重载切换数据库类型（失败自动回退旧连接池）
  - `database.yml` 独立配置文件（类型/连接参数/表前缀/数据保留天数）
  - Schema 自动迁移，支持 H2 和 MySQL 双方言
- **对话历史持久化服务**：玩家对话记录自动保存到数据库，重启不丢失
  - Write-Behind 异步刷盘：内存消息队列 → 每 30 秒批量写入，阈值（≥20 条）即时触发
  - 懒加载历史（Lazy Loading）：玩家首次发言时从 DB 自动加载历史到内存，平滑衔接上下文
  - 玩家退出时立即 flush，确保不丢数据；过期数据定时清理（可配置保留天数）
- **玩家画像系统**：AI 记住每个玩家的行为偏好和游戏风格，提供更个性化的服务
  - 登录统计（首次登录、累计时长、登录次数）、行为偏好、游戏风格、LLM 分析结果持久化
  - 内存缓存 + DB 异步读写 + 版本戳防竞态，秒级响应
  - 登录/退出时自动触发 LLM 画像分析（三重门控：时间间隔 + 消息数量 + 滑动窗口）
  - 五点画像维度：游戏风格、性格特征、内容偏好、沟通风格、特别观察
  - 画像摘要可在 AI 对话中动态注入系统提示词，让 AI 更懂玩家
  - 示例："AI 会记得一个喜欢 PVP 的玩家，并在交流时调整回复风格"
- **社交关系图谱**：AI 自动追踪玩家间的社交关系强度，形成社交网络
  - 三种交互来源自动加权增强：私聊（+0.01）、TPA 传送（+0.02）、Skill 交互（+0.005）
  - 每日关系衰减（5%）+ 弱关系自动清理，保持数据新鲜度
  - Skill 日志智能提取：定期扫描白名单 Skill 的玩家交互记录，自动增强相关玩家的社交关系
  - 水位标记分布式安全机制（DB 行锁 `SELECT FOR UPDATE`），多子服不冲突
  - 示例：玩家登录时 AI 问候语可提到"你的好友 Steve 也在线"
- **服务器事件采集系统**：自动记录服务器中发生的里程碑事件，玩家离线后也能回顾
  - 玩家死亡、成就解锁、等级提升自动记录到 `kca_server_event` 表
  - 全球市场交易事件（上架、售出、收款）自动记录（卖家视角）
  - 私聊和 TPA 传送指令无需额外配置，自动增强社交关系强度
  - 离线事件聚合器：玩家登录时可回顾离线期间发生的服务器大事
- **AI 登录问候系统**：玩家登录时 AI 自动发送个性化问候语
  - 首次登录：欢迎新玩家，介绍 AI 助手功能和服务信息
  - 回归登录：三大分类数据聚合架构
    - **分类一**：玩家自己的离线事件（市场交易、成就、等级变化等）
    - **分类二**：好友离线期间的动态（JOIN player_profile 获取名称，展示好友的里程碑事件）
    - **分类三**：摘要统计（累计时长/登录次数/加入天数，仅触及明显里程碑时提及；上次游玩亮点）
    - 示例："欢迎回来！你已经离线 3 天了，这期间 Steve 达成了 2 个成就，你的钻石也卖出去了"
  - 冷却机制（可配置），避免频繁骚扰
  - `greeting.yml` 独立配置文件（开关/提示词模板/冷却/三大分类事件数量/服务器信息）
  - 新增 `OutputScenario.GREETING` 场景，输出载体独立可配
- **统一定时任务调度器**：所有周期性后台任务集中管理
  - `ManagedTask` 接口 + `TaskScheduler` 统一管理器，5 个托管任务
  - CAS 互斥保护 + 结构化日志 + 运行统计
  - `/kilacraft tasks` 命令查看任务运行状态（需 `kilacraft.tasks` 权限，默认 OP）
- **技能执行审计日志**：所有技能执行自动记录，支持回溯分析
  - 记录：玩家 UUID、技能名、动作、参数、执行结果、耗时、触发来源
  - 异步写入 `kca_skill_log` 表，不影响技能执行性能
  - 社交关系提取器消费此日志表，自动发现玩家间的 Skill 交互

### 🔧 优化改进
- **内置枚举替代知识库文件**：音效、粒子、统计等游戏内置枚举数据从知识库 Markdown 文件迁移至专用枚举注册表，检索更精准、不占用知识库空间、加载更快
- **自定义 I/O 线程池**：替代 JDK 默认的 ForkJoinPool.commonPool()，提供自适应有界线程池
  - 核心线程 = CPU 核数，最大线程 = min(CPU×4, 128)，队列容量与最大线程一致
  - 安全拒绝策略：满载时丢弃任务并记录警告，绝不阻塞 Bukkit 主线程
  - CPU 感知自适应：2 核 VPS 到 64 核大型服务器均有合理配置
  - 初始化/关闭时输出详细日志（核心/最大/队列/服务端模式）
- **HTTP 连接池优化**：OkHttp ConnectionPool 连接数与 IO_POOL 最大线程数对齐，避免线程因等连接而阻塞
- **挂机任务智能回调机制**：回调任务触发时，LLM 能在执行结果区域看到事件触发原因，回复更准确
- **挂机任务第一人称视角**：当玩家监视自己时，AI 以第一人称回复（"你说了：好的"），不再以旁观者视角描述
- **挂机任务回调事件描述统一**：所有 20 种挂机任务的回调路径与通知路径使用一致的事件描述格式
- **意图识别时序语义理解**：LLM 能正确理解"小麦熟了之后查价格"、"等他上线了告诉我"等时序表达，将后续动作放入回调而非并行步骤
- **AI 回复质量优化**：
  - 禁止在回复中称呼玩家 ID，对话更自然
  - 技能执行失败时，AI 根据失败原因自然解释，不再触发绝对禁令拒绝回复
  - AI 不再暴露内部技术细节（步骤 ID、枚举原始值、统计计数等），全部转为玩家可理解的自然语言
- **config.yml 注释阅读体验优化**：全文件双语注释统一为"先中文、后英文"连续排列，无论哪种语言阅读都更连贯
- **配置架构重构**：4 个新独立配置 Manager 替代 847 行 `config.yml`
  - `LLMConfigManager` → `llm.yml`（温度/Token/系统提示词/Agent 能力配置）
  - `OutputConfigManager` → `output.yml`（输出管线/流式/音效/5 种载体场景配置）
  - `KnowledgeConfigManager` → `knowledge.yml`（分段/BM25/Embedding/自定义词典）
  - `GreetingConfigManager` → `greeting.yml`（AI 问候系统配置）
  - `ConfigManager` 改为代理模式，消费方无需感知底层拆分
- **对话来源标识**：所有对话记录携带来源标识
  - 支持 6 种来源：聊天监听、`/ai` 命令、控制台插件调用、控制台交互、登录问候、挂机回调
  - AI 回复持久化时自动携带来源标识，便于数据分析和问题排查
- **热重载数据库配置**：`/kilacraft reload` 支持热重载数据库配置（含数据库类型 H2/MySQL 切换），失败时自动回退到旧连接池
- **关闭时序重构**：优化插件卸载流程，确保数据不丢失
  - 新顺序：定时任务取消 → 刷盘剩余消息 → 写出所有玩家画像 → 等待 IO 线程池完成 → 关闭数据库连接池
- **线程安全增强**：`ConversationManager.chatMode` 从 `HashMap` 升级为 `ConcurrentHashMap`
- **流式输出修复**：修复特殊场景下流式输出载体被硬编码为 `NORMAL_CHAT` 的问题，确保问候等场景流式输出正确
- **SkillSecurityFilter 增强**：新增 `getOnlinePlayerNames()` / `getOnlineUuidToName()` 公开 API，供社交关系等模块在异步线程安全获取在线玩家信息
- **pom.xml 新增依赖**：HikariCP 5.1.0（连接池）、H2 2.2.224（嵌入式数据库）、MySQL Connector/J 8.4.0（provided），均通过 Maven Shade 重定位避免冲突

### ⚠️ 兼容性 — 配置迁移指南

> **重要：升级前请完整备份 `plugins/Kilacraft-AI/` 目录！**

此版本将 847 行 `config.yml` 按配置域拆分为 6 个独立文件，提升可维护性。首次启动后，插件会自动生成以下新文件（使用内置默认值）：
- `database.yml`（数据库配置，默认 H2 嵌入式，同时支持 MySQL 外挂数据库）
- `llm.yml`（LLM API 配置 + Agent 能力配置）
- `output.yml`（输出管线配置，含音效）
- `knowledge.yml`（知识库检索/分段/BM25/Embedding/自定义词典）
- `greeting.yml`（AI 问候系统配置，默认关闭）

**迁移步骤：**
1. 备份整个 `plugins/Kilacraft-AI/` 目录
2. 启动服务器，让插件生成新配置文件
3. 对照下表，将旧 `config.yml` 中自定义的配置值复制到对应新文件中
4. 执行 `/kilacraft reload` 使迁移后的配置生效
5. 迁移完成后，旧 `config.yml` 中的 `llm:`、`agent:`、`output:`、`knowledge:` 段可删除（保留也不影响运行，插件不再读取）

**配置迁移对照表：**

| 旧位置（config.yml） | 新文件 | 新位置（key path 保持不变） |
|---|---|---|
| `llm:` 整个段 | `llm.yml` | `llm:` |
| `agent:` 整个段 | `llm.yml` | `agent:` |
| `output:` 整个段 | `output.yml` | `output:` |
| `knowledge:` 整个段 | `knowledge.yml` | `knowledge:` |
| （新增，无旧配置） | `database.yml` | `database:` |
| （新增，无旧配置） | `greeting.yml` | `greeting:` |

**保留在 config.yml 不变：**
- `settings:`（语言、调试模式）
- `messages:`（AI 消息前缀）
- `command_skill:`（命令 Skill 安全控制）
- `afk_task:`（挂机任务）
- `security:`（安全配置）

**新增数据库表（首次启动自动创建）：**
- `kca_conversation`：对话历史持久化
- `kca_player_profile`：玩家画像数据
- `kca_server_event`：服务器事件记录
- `kca_social_relation`：社交关系强度
- `kca_skill_log`：技能执行审计日志
- `kca_watermark`：水位标记（分布式互斥）

**新增权限节点：**
- `kilacraft.tasks`：查看定时任务运行状态（默认 OP）

**新增依赖（已内置于 JAR）：**
- HikariCP 5.1.0（数据库连接池）
- H2 2.2.224（嵌入式数据库）

**完全向后兼容**：默认 H2 嵌入式数据库零配置即可运行，同时支持 MySQL 外挂数据库。现有功能无需修改。

## v1.4.6 - BukkitStatsSkill 原版统计查询、环境感知 API、三层库存设计
