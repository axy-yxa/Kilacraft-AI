## v2.1.1 - 两阶段意图识别架构、Skill SPI 结构化响应（needInfo 二次确认）、提示词体系重构、LLM 思考模式治理

### ✨ 新增功能
- **两阶段意图识别架构（本次核心）**：将原本「单次全量技能清单送 LLM」拆为两阶段，显著降低 Token 消耗
  - **Phase 1（粗选）**：仅发送每个技能的一行 `name + description`，LLM 判断需要哪些技能类别；纯闲聊直接返回 `null`，跳过 Phase 2 走普通 AI 对话
  - **Phase 2（精选）**：仅对 Phase 1 命中的技能发送全量信息（actions + hints），完成动作选择与参数提取；并对 `skill_name` 做白名单校验，无效名称拒绝执行
  - **量化收益**：
    - **改造前基线**（单阶段，每次识别）：主规则段 ~2.6 万 + 全部技能全量 ~8 万（含 BukkitAPI 77 动作 ~3.8 万）≈ **10.6 万字符**
    - **纯闲聊**：仅 Phase 1 判定（返回 `null`，不发 Phase 2）≈ **0.8 万字符**，较基线 **↓ ~92%**
    - **普通技能**（命中 1 个内置技能，取全量中位数 ~3.1 千字符）：Phase 1 + Phase 2 ≈ **3.8 万字符**，**↓ ~65%**
    - **复杂技能**（命中含 BukkitAPI 77 动作）：Phase 1 + Phase 2 ≈ **7.3 万字符**，**↓ ~32%**
    - token 换算（中文混合内容 ~0.6 token/字符）：基线 ≈ 64K → 三场景 ≈ 4.8K / 22.6K / 43.5K
  - 响应速度：两阶段增加一次极轻量的 Phase 1 调用，但每次识别不再携带全量技能清单，净延迟取决于模型与网络
- **Skill SPI 结构化响应架构（新增 `needInfo` 二次确认）**：Skill 响应语义从「message 字符串前缀」升级为类型化状态
  - **新增 `SkillResult.needInfo(message)` 工厂方法**：第三方 Skill 实现「需补全信息 / 二次确认」的官方契约（缺参数引导、大额转账确认等）；框架输出 `[NEED_INFO]` marker，意图识别据此驱动确认流
  - `SkillResult` 新增类型化 `SkillStatus` 枚举（SUCCESS/FAILURE/NEED_INFO）+ `getStatus()`；新增归一化层 `SkillResultFormatter` 在输出给 LLM 时统一打 `[SUCCESS]/[FAILURE]/[NEED_INFO]` 标记，Skill 写裸文本即可，杜绝各 Skill 手写前缀导致的不一致与双标
  - SPI Jar 新增 `SkillStatus` 类（第 6 个类）
- **意图识别提示词体系重构**（中英文同步）：新增「三条不可违反」最高优先级规则（不确定时默认走多步骤）；单意图/多步骤决策重构为三条件判定（必需参数由用户提供 + 单动作可完成 + 不依赖其他动作返回值）；算术占位符统一支持 `amount`/`quantity`/`price`/`threshold`；参数缺失强制「先查后操作」（严禁必需参数为 null）；Phase 1 粗选定位强化（宁多勿漏）
- **LLM 思考模式治理**：普通对话路径对默认开启思考的模型（MiMo、DeepSeek V4+、GLM 4.5+、Kimi K2+、Qwen3、Grok 4、Doubao thinking、MiniMax-M3 等）自动关闭思考；admin 推理路径按模型族注入启用参数；适配 OpenAI o-series / Doubao thinking 的 `max_completion_tokens`。解决思考 token 与输出 token 共享 `max_tokens` 预算导致 MC 场景（配额较小）实际输出为空
- **占位符算术求值工具（ArithmeticUtil）**：求值逻辑抽离为公共工具类，应用范围从多步骤任务标量参数（amount/quantity/price）扩展至 CUSTOM 任务 `threshold`，支持「比当前血量少 5」等相对阈值（`{step_0.health}-5`）。仅单次二元运算（+ - * /），纯正则无注入风险
- **JSON 自动修复工具（JsonSafeGetUtil）**：三阶段修复（过滤多余闭合 → 补全缺失闭合 → 移除尾部逗号），交叉嵌套时放弃修复，统一替换多处重复实现
- **启动时版本更新检测**：异步检查 GitHub 最新版本，有新版时控制台彩色框线提示，静默失败

### 🔧 优化
- **诊断模型回退机制**：`admin.yml` 未配置推理模型时自动回退使用 `llm.yml` 基础对话模型（仅复用 url/key/model，max_tokens/timeout 仍用诊断专用值避免报告截断），降低健康监控使用门槛
- **健康监控不可用分层诊断**：逐一检查前置条件（模型 / 守护开关 / Spark 安装），给出精准提示；诊断报告头部新增「诊断模型」行标注实际生成模型
- **DB 历史加载条数调优**：`loadFromDB` limit 由 `maxHistory×2` 调整为 `maxHistory`（默认 20），减少冗余加载
- **挂机任务字符串条件值展示优化**：`EvaluationResult` 新增 `actualValueStr`，字符串条件（如方块类型）显示真实值而非 0/1 占位
- **LLM 空响应友好提示**：流式响应为空时向玩家返回「AI 暂时无法回复」，不再收到空消息（同时记录 SSE chunk 数与最近原始数据辅助排查）
- **JSON 场景禁用 `max_tokens`**：意图识别、画像分析等场景不再设 `max_tokens`，避免复杂 JSON 被截断；GenericBukkitAPI 描述增强提升 Phase 1 分类准确率
- **并发与线程安全**：`ConversationManager` 历史队列升级为 `ConcurrentLinkedDeque` + 自动 trim（MAX_HISTORY_SIZE=100）；`AFKTaskManager` 原子注册防超限；`ProfileManager.flushAllProfiles` 单连接批量更新防级联失败
- **代码精简与可观测性**：LLMProvider 接口精简、ThinkingModelCapable 升级为功能接口；SkillIntentRecognizer 异常分层捕获补完整堆栈；GreetingPromptBuilder 事件摘要合并消除 ~140 行重复；历史记录访问统一；清理冗余 i18n 包裹与翻译死键
- **配置热重载硬化**：`PersonalitiesConfigManager` 改为快照替换模式，`LLMConfigManager` 全字段 volatile
- **Embedding 检索优化**：chunk 向量范数预计算缓存，余弦相似度运算量降低 2/3
- **`reconcileOnlineProfiles` 单连接批量**：与 `flushAllProfiles` 模式对齐
- **画像分析提示词时效性优化（中英文同步）**：不再提炼余额、坐标、库存数等易过期的瞬时数据，只保留长期稳定的特征，避免画像残留过期错误信息；已有画像会在下次分析时自动清理
- **内置 Skill 全量迁移到结构化输出**：MarketActionSkill / CMISkill / MarketQuerySkill / CommandSkill 剥离手写的 `[FAILURE]`/`[NEED_INFO]` 前缀（约 80 处），统一由框架归一化层打标；`TaskExecutor` 多步骤内部跳过状态改为类型化枚举，移除旧的中文前缀嗅探（消除英文环境下分类失配的潜在 bug）
- **二次确认与提示词治理（中英文同步）**：意图识别提示词新增「二次确认流」规则（玩家确认上轮操作时从历史读取具体值再调用）；`llm.yml` 系统提示词统一说明 marker 语义；`messages_en.yml` 剥离嵌在 key/value 里的标记前缀并修复重复 key；`Skill-SPI-接入文档.md`（zh+en）全面重写

### 🐛 修复
- 修复 `BM25Scorer.countOccurrences` 空关键词死循环导致 `mvn test` 永久卡死
- 修复 `KnowledgeRetriever.splitByFixedSize` 内容长度恰好等于 MAX_CHUNK_SIZE 时重叠回退逻辑凭空多切一段
- 修复 `ConversationPersistenceService.mergeLoadedHistory` 在 `loadedHistory` 与 `playerHistory` 为同一对象时 `clear()` 清空自身导致历史丢失

- 修复画像分析 JSON 解析偶发失败、CUSTOM 任务 `condition_plan` 空值 NPE、关服 `flushAllProfiles` 连接异常级联失败、`ConversationManager` 非线程安全 `ArrayDeque` 并发数据丢失
- **安全与稳定性加固**：修复多项稳定性与安全边界问题；新增近期活跃玩家缓存强化数据隔离

## v2.1.0 - 服主管理功能（服务器健康监控、玩家行为分析、审计日志查询）、代码包架构重组

### ✨ 新增功能
- **服务器健康监控系统**：AI 驱动的智能服务器监控与诊断系统，解决服务器卡顿难定位、性能问题排查耗时的问题
  - **零配置自动监控**：守护线程 24/7 后台运行，每 10 秒检测 TPS、MSPT、CPU 等指标，异常自动触发诊断
  - **AI 智能诊断**：使用推理模型（如 DeepSeek R1）进行深度性能分析，自动生成 Markdown 诊断报告，精准定位性能瓶颈
  - **服务器活动指标采集**：采样窗口内采集各世界区块加载变化和玩家分布数据，弥补 Profiler 无法捕获非 CPU 活动（I/O、磁盘、网络）的数据盲区
  - **方法级热点定位**：基于 Spark Profiler 的调用栈分析，精确到代码层面，识别具体插件的性能影响。auto 模式采用全时段采样，与 manual 模式保持一致
  - **手动精准分析**：支持 `/kilacraft profile start [时长]` 命令，服主可按需分析特定时段，解决间歇性性能问题
  - **智能防抖机制**：告警冷却、滑动窗口频率限制，避免资源耗尽，确保系统稳定
  - **外部通知推送**：自动触发诊断分析完成后，可向 Discord 或钉钉群机器人推送告警通知，服主不在线也能第一时间获悉服务器状况。Discord 支持 Embed 卡片消息，钉钉支持 Markdown 文本 + 可选 HMAC-SHA256 签名安全加固。推送内容仅包含告警原因、实时快照指标和 AI 诊断结论摘要，不含完整诊断报告附件，避免敏感信息泄露
  - **独立配置管理**：新增 `admin.yml` 配置文件，集中管理监控阈值、推理模型、外部通知渠道、诊断提示词等
- **服务器健康告警查询（ServerHealthSkill）**：通过自然语言查询历史健康告警记录
- **玩家行为分析（PlayerAnalysisSkill）**：在线人数趋势、活跃玩家排行、新玩家流入、画像分析覆盖率、社交图谱洞察、指定玩家社交关系查询
- **审计日志查询（AuditLogSkill）**：查看 AI 技能执行记录、使用统计、失败日志
- 新增管理员权限节点：`kilacraft.admin.health`、`kilacraft.admin.player`、`kilacraft.admin.audit`（默认仅 OP）
- 新增 Spark 插件作为软依赖，无 Spark 时管理功能自动禁用，不影响其他功能。Paper 1.21+/Folia/Purpur/Leaf/Pufferfish 等服务端已内置 Spark，无需额外安装
- 新增 `/kilacraft notify test` 命令，可测试 Discord/钉钉通知渠道配置是否正确
- 新增诊断报告文件输出（Markdown 格式，自动保存到 `plugins/Kilacraft-AI/reports/`）

### 🔧 优化
- **画像分析提示词时效性优化**：首次分析排除临时性瞬时状态，增量分析主动清理已过时的临时性内容，避免短生命周期事务在多个版本中残留
- **自监控文本逻辑复用**：`DiagnosticReportGenerator.appendSelfMonitoring()` 提取为公共静态方法，`ServerHealthGuardian` 委托调用，消除重复代码
- **Admin Skill 查询输出全面格式化**：所有服主管理 Skill（PlayerAnalysisSkill 6 个 action、AuditLogSkill 3 个 action）的 message 输出全面优化——时间戳可读化（epoch→yyyy-MM-dd HH:mm）、UUID→玩家名反查（在线缓存 + 库查询二级策略）、事件类型翻译（PLAYER_LOGIN→登录）、关系强度等级化（数值→陌生/点头之交/普通朋友/好友/密友），提升 AI 二次分析的输入可读性
- **AI 提示词语气统一**：普通对话和二次分析的提示词统一为简洁平实风格，与问候系统保持一致。移除“热情有趣/像朋友聊天”等措辞，同步更新配置文件和代码硬编码默认值
- **MySQL 连接失败自动回退 H2**：启动和热重载时 MySQL 不可用自动回退到 H2 内置数据库，确保持久化功能正常可用
- **审计日志查询支持查询其他玩家**：`audit_log.query_logs` 加入安全白名单，管理员可查询指定玩家的技能使用记录
- **热重载数据库切换资源释放顺序优化**：调整为先关闭旧 Provider 再创建新 Provider，避免 H2 TCP 端口冲突
- **热重载 DAO tablePrefix 刷新一致性**：所有持有 DAO 的模块在热重载时重建 DAO 以反映最新的表前缀
- **AI问候系统提示词与注入内容全面优化**：健康告警三层结构化输出（异常指标/涉及插件/热点方法+触发路径）、注入内容视角修正（AI视角用玩家名而非"你"）、上次位置世界名前缀、提示词规则全面强化（规则3里程碑泛化与防模糊描述）及国际化全链路审计治理

### 🐛 修复
- **修复热重载切换数据库后玩家画像版本号重置（V8→V1）**：`reconcileOnlineProfiles()` 未从新数据库重新加载画像到内存缓存，导致运行时状态覆盖新库的历史画像数据
- **修复 `databaseManager` 未初始化时 `initializeAdminSystem` / `syncGuardianState` 的 NPE**

## v2.0.2 - 群组服数据隔离、Skill权限预检、增量画像分析、画像历史快照、占位符算术、JSON自动修复

### ✨ 新增功能
- **增量画像分析**：画像分析从"每次全新生成"升级为"旧画像 + 新对话融合更新"，玩家长期积累的特征不会被短期波动覆盖
  - 提示词支持中英文双语配置（首次分析 / 增量分析分开配置），支持热重载
- **画像历史快照**：新增 `kca_profile_snapshot` 表，每次分析自动保存画像快照，支持追溯任意版本的画像内容与分析时间范围，永久保留
- **群组服数据隔离**：支持 BungeeCord/Velocity 跨子服数据共享与隔离
  - `database.yml` 新增 `group.server_id` 配置，需删除旧配置文件重新生成
  - 对话历史、服务器事件、技能审计日志按 `server_id` 隔离；玩家画像与社交关系天然跨服共享（无 `server_id` 字段，不可配置）
