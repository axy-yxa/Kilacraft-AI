## 版本兼容

**最低要求：Minecraft 1.16.5 + Java 17**

|   Minecraft 版本   |  Java 要求 |             支持的服务端            |                                  说明                                 |
| :--------------: | :------: | :---------------------------: | :-----------------------------------------------------------------: |
|    **1.16.5**    | Java 17+ | Paper / Purpur / Leaf / Folia | CraftBukkit/Spigot 不支持 Java 17+，需加 `-DPaper.IgnoreJavaVersion=true` |
|  **1.17 - 1.19** | Java 17+ |               全部              |         Spigot / Paper / Purpur / Leaf / Folia / CraftBukkit        |
| **1.20 - 1.21+** | Java 21+ |               全部              |                            服务端要求 Java 21                            |

一套 JAR 包兼容所有版本，基于 Spigot 1.16.5 API 开发，完整支持 Folia 区域化线程调度。

***

## 核心优势

- **零中间件** — 一个 JAR 文件即可运行，无需数据库、Redis 或任何外部服务
- **极低资源占用** — 小型服务器 8-12 MB，大型服务器 30-50 MB，异步非阻塞不卡服
- **开箱即用** — 5 分钟完成配置，支持所有 OpenAI 标准格式的 LLM 厂商
- **高度可定制** — 知识库、人格系统、意图识别提示词、输出载体全部可配置
- **开放生态** — SPI 接口允许第三方插件注册自定义 Skill，5 分钟即可接入
- **中英双语** — 完整的国际化架构，配置 `language: zh/en` 一键切换

## 快速开始

### 1. 安装

下载最新的 `Kilacraft-AI.jar`，放入服务器 `plugins/` 目录，启动服务器。

### 2. 配置 API

编辑 `plugins/Kilacraft-AI/config.yml`，填入你的 LLM API 信息：

```yaml
llm:
  api_url: "https://api.deepseek.com/v1/chat/completions"
  api_key: "your-api-key"
  model: "deepseek-chat"
```

支持所有 OpenAI 标准格式的厂商（DeepSeek、智谱AI、Moonshot、OpenAI、Groq、硅基流动、Gemini、OpenRouter 等），只需修改 `api_url` 和 `model` 即可切换。

### 3. 测试

```
/kila 你好
```

看到 AI 回复即配置成功。

> 重载配置使用 `/kilacraft reload`，重载知识库使用 `/kilacraft knowledge reload`，重载人格使用 `/kilacraft personalities reload`。

## 智能对话

### 三种交互模式

```
# 命令模式
/kila 怎么获得钻石？

# 连续对话模式
/kilacraft chat
> 我想建个农场
> AI: 好主意！你想种什么作物？
> 小麦吧
> AI: 种植小麦需要锄头、水桶和种子...

# 关键词触发（公共频道）
@ai 这个怎么做？
```

命令别名：`/kilacraft`、`/kila`、`/ai`、`/zm`

### 流式输出

启用后 AI 回复逐字实时显示，消除等待感：

```yaml
output:
  stream:
    enabled: true
```

支持 5 种输出载体，按场景独立配置：

|        载体       |     效果     |    适合场景   |
| :-------------: | :--------: | :-------: |
|   **SIDEBAR**   | 右侧边栏，不遮挡视野 | 长文本回复（推荐） |
|  **BOSS\_BAR**  |    顶部横条    |   中等长度文本  |
| **ACTION\_BAR** |    物品栏上方   |   短文本提示   |
|     **CHAT**    |     聊天栏    |    默认方式   |
|    **TITLE**    |    屏幕中央    |   短文本高亮   |

### AI 回复音效

AI 开始回复时自动播放提示音效，仅触发玩家可听到：

```yaml
output:
  sound:
    enabled: true
    sound_name: "ENTITY_PLAYER_LEVELUP"
    volume: 0.5
    pitch: 1.2
```

## 知识库增强

让 AI 了解你的服务器规则、玩法、FAQ。只需在 `plugins/Kilacraft-AI/knowledge/` 目录放入 Markdown 或 TXT 文件：

```markdown
# server_rules.md

## 如何获得领地？
使用 /claim 命令来圈定你的领地。需要至少 10 个金币。

## 怎么赚钱？
可以通过挖矿、钓鱼或在玩家商店出售物品来赚钱。
```

执行 `/kilacraft knowledge reload` 加载，玩家提问时 AI 会自动检索并引用：

```
玩家: 我怎么才能圈地？
AI: 你可以使用 /claim 命令来圈定你的领地。需要至少 10 个金币。
```

支持自定义词典，添加服务器特有术语可显著提升检索准确度：

```yaml
knowledge:
  custom_dictionary:
    enabled: true
    words:
      - "圈地"
      - "领地"
      - "红石"
      - "刷怪塔"
```

## 意图识别与任务编排

Kilacraft-AI 不是简单回答问题，而是理解玩家真实意图并自动调用对应功能：

```
用户输入 → LLM 意图识别 → 执行技能/任务 → 分析结果 → 生成自然语言回复
```

### 单意图

简单查询直接执行：

```
玩家: 钻石多少钱？
AI: 钻石当前价格：$100.00/个
```

### 多步骤任务

复杂请求自动分解为有序步骤：

```
玩家: 我手上拿着的东西市场上有人卖吗？多少钱？
  ↓
步骤 1: 查询玩家手持物品 → 钻石剑
步骤 2: 查询钻石剑市场在售情况 → 有在售，库存 2 个
步骤 3: 查询钻石剑价格 → $500.00/个
  ↓
AI: 你手上是钻石剑，市场上有 2 个在售，价格 $500.00/个。
```

步骤之间支持数据自动传递（`{step_1.item_name}`），支持数组索引（`{step_1.homes[0].home_name}`）。

### 容错机制

- 部分步骤失败不中断整个流程，LLM 基于成功步骤的结果尽可能回答
- 意图识别失败时自动回退到普通 AI 对话

## 原版数据查询

### Bukkit API（72 个内置接口）

AI 直接查询玩家状态、世界信息、服务器信息，无需写代码：

```
玩家: 我手上拿着什么？     → 你主手拿着：钻石剑 x1
玩家: 我还有多少血？       → 生命值：18.5/20.0
玩家: 现在是什么时间？     → 世界时间：06:00（早晨）
玩家: 天气怎么样？         → 当前天气：晴朗
玩家: 服务器有多少人在线？ → 在线玩家：15/100
```

覆盖类别：

|   类别  |  数量 |                示例                |
| :---: | :-: | :------------------------------: |
| 玩家物品栏 |  2  |       主手/副手物品、盔甲装备、背包内容、末影箱      |
|  玩家状态 | 10+ |  生命、饥饿、氧气、经验、着火、冰冻、药水效果、蹲下/奔跑... |
|  玩家信息 | 15+ | 位置、游戏模式、飞行、Ping、死亡点、目标方块、语言设置... |
|  世界信息 | 20+ |   时间、天气、生物群系、温度、湿度、实体统计、袭击事件...  |
| 服务器信息 |  7+ |     在线玩家、版本、MOTD、世界列表、TPS...     |
|  环境感知 | 14+ |   脚下方块、上次受伤原因、世界边界、无敌帧、下落距离...   |

所有 API 均为只读操作，每个类别有独立权限节点，可通过 LuckPerms 等插件精细控制。

### 原版统计数据

查询玩家 Minecraft 原版累计统计（生涯记录）：

```
玩家: 我总共死了多少次？   → 总死亡次数：42
玩家: 我杀了多少僵尸？     → 击杀生物（僵尸）：15
玩家: 我走了多远？         → 行走距离：12.5 公里
玩家: 我挖了多少钻石矿？   → 挖掘方块（钻石矿）：128
```

支持 80+ 统计枚举，自动单位转换（厘米→公里、tick→可读时间）。

## 挂机任务系统

让 AI 帮你"盯梢"，通过自然语言创建后台监控任务，条件满足时自动通知或执行操作。

### 事件监听（12 种）

```
玩家: 帮我盯着 Steve 上线
AI: 好的！Steve 上线后会第一时间通知你。

[30 分钟后...]
🔔 Steve 已上线服务器！
```

```
玩家: 盯着 Steve 上线，上线后查一下他手里拿的什么
AI: 好的！Steve 上线后会自动查询他手中的物品。

[Steve 上线后...]
🔔 Steve 已上线！查询到他主手拿着钻石剑 x1。
```

|    监控类型   |      说明      |
| :-------: | :----------: |
|  玩家上线/下线  |   监视指定玩家上下线  |
|  玩家死亡/重生  |   监视死亡事件和重生  |
| 玩家传送/切换世界 |    监视位置变动    |
|    等级变化   |   监视玩家升级/降级  |
|    天气变化   |    监视世界天气    |
|  睡眠/物品损坏  | 进入床、离开床、物品损坏 |

### 自定义条件轮询

监控任意 Skill 返回的数值条件：

```
玩家: 当我的血量低于 10 时告诉我
玩家: 当我的余额低于 1000 时提醒我
玩家: 当我达到 30 级时帮我查一下钻石价格
```

管理命令：`/kilacraft afk` 查询、`/kilacraft afk cancel` 取消。每人同时仅一个任务。

## 人格系统与 NPC 对话

### 人格配置

在 `personalities.yml` 中定义不同风格的 AI 人格：

```yaml
common_prompt: "你是 Minecraft 服务器的 NPC，正在和玩家 {player} 对话。"

狐狸: |
  你是一只聪明的狐狸 NPC，说话俏皮可爱。
  喜欢用"~"结尾，经常使用表情符号。

严厉教师: |
  你是一位严厉的 Minecraft 教师，对学生要求很高。
  说话简洁直接，但会耐心解答问题。
```

### NPC 智能对话

有两种方式让 MythicMobs NPC 拥有独立人格：

**方式一：回调命令**（推荐）

```yaml
# MythicMobs 技能配置
fox_npc_skill:
  Skills:
  - cmd{c="kilacraft plugins 狐狸 服务器的规则是什么 <caster.uuid> myplugin handle_ai {response} <caster.name>"} @self
```

AI 生成回复后自动执行回调命令，你的插件通过回调接收并显示回复。

**方式二：MythicMobs 占位符**

使用内置占位符 `<caster.ai.answer{type=人格名称}>` 直接获取 AI 回复：

```yaml
# MythicMobs 技能配置（先触发 AI 生成，再用占位符读取回复）
fox_npc_skill:
  Skills:
  - cmd{c="kilacraft plugins 狐狸 服务器的规则是什么 <caster.uuid>"} @self
  - message{msg="<caster.ai.answer{type=狐狸}>"} @trigger
```

占位符会读取并消费缓存中的 AI 回复，未就绪时返回 `UNDEFINED`。支持动态参数（如 `{type=<skill.puppet>}`）。

> 插件命令仅限控制台执行，每个 `UUID_人格` 组合有独立历史记录。

## 插件集成

### GlobalMarketPlus（经济系统）

```
玩家: 钻石多少钱？       → 钻石当前价格：$100.00/个
玩家: 我还有多少余额？   → 你的余额：$12,580
玩家: 市场上有什么商品？ → 当前在售：钻石 x15、铁锭 x32...
玩家: 钻石有人卖吗？     → 钻石有在售，库存 2 个
```

7 个只读查询动作，不会消耗物品或金钱。

### CMI（传送与玩家信息）

```
玩家: 帮我回家           → AI 查询家列表后传送到指定家
玩家: 传送到主城         → AI 查询地标列表后传送到指定地标
玩家: 传送到 Steve       → AI 发送 TPA 传送请求
玩家: Steve 在线吗？     → Steve 当前在线，AFK 状态：否
玩家: 有哪些地标？       → 当前地标：主城、资源区、PVP 竞技场...
```

8 个动作（5 查询 + 3 传送），传送使用 TPA 请求模式，AFK/隐身状态自动识别。

### 音效与粒子效果

```
玩家: 给我放个升级音效   → 播放 ENTITY_PLAYER_LEVELUP（仅自己听到）
玩家: 显示一些爱心粒子   → 显示 HEART 粒子（仅自己看到）
```

效果仅对触发玩家可见/可听，自然语言触发。

### 命令执行

AI 以玩家身份执行服务器命令，完全继承服务器权限系统：

```
玩家: 帮我回死亡点  → 执行 /back
```

默认关闭，需手动开启。玩家没有的权限 AI 也无法越权。

## 开放 SPI 接口

第三方插件开发者可以通过 Skill SPI 接口将自己的功能暴露给 AI：

- **API JAR** 仅 5 KB（compileOnly 依赖）
- 实现 `SkillProvider` 接口即可注册自定义 Skill
- 通过 Bukkit `ServicesManager` 自动发现和注册
- 内置错误隔离，第三方 Skill 异常不影响核心流程

适合集成的插件类型：领地系统、排行榜、RPG 系统、公会系统、成就系统、世界管理等。

详见 [Skill SPI 接入文档](./Skill-SPI-接入文档.md)。

## 安全机制

### 玩家数据隔离

内置非合作式安全过滤机制，在每次 Skill 执行前自动运行：

- 扫描 Skill 参数中的所有值，检测是否包含其他在线玩家名
- 非本人且不在白名单 → 自动替换为当前玩家名（消毒），Skill 继续执行
- 白名单机制：CMI 传送请求、挂机任务、命令执行等需要操作其他玩家的 Skill 已预置白名单

### 内置 Skill 安全性

|     Skill     |          安全性          |
| :-----------: | :-------------------: |
| Bukkit API 查询 |    只读，仅调用 getter 方法   |
|     原版统计查询    |           只读          |
|      市场查询     |      只读，不会消耗物品或金钱     |
|     CMI 传送    | TPA 请求模式，由 CMI 自身处理权限 |
|      命令执行     |  以玩家身份执行，完全继承服务器权限系统  |
|     音效/粒子     |       仅调用者可见/可听       |
|      挂机任务     |     白名单放行，有并发防重入保护    |

### 第三方 Skill 防护

即使第三方 Skill 尝试操作其他玩家，安全过滤器也会自动消毒。建议安装前审查代码来源。

## 常见问题

**Q: API 费用高吗？**
以 DeepSeek 为例，单次对话约 ¥0.001-0.002。设置冷却时间（默认 5 秒）可有效控制成本。

**Q: 支持哪些 LLM？**
所有 OpenAI 标准格式的厂商均可，包括 DeepSeek、智谱AI、Moonshot、OpenAI、Groq、硅基流动、Gemini、OpenRouter 等。不支持思考/推理模型（如 deepseek-reasoner、o1）。

**Q: 会卡服吗？**
不会。所有 API 请求异步执行，内存占用 8-50 MB，HTTP 连接池复用，支持流式响应降低延迟。

**Q: 如何更新？**
备份 `plugins/Kilacraft-AI/` 目录保留配置，替换 JAR 文件，重启服务器。
