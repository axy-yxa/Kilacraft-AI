# Kilacraft-AI - 知识库增强指南

> **版本**: v1.4.1  
> **说明**: 本文档详细介绍如何使用 RAG（检索增强生成）技术，让 AI 基于你的服务器文档提供准确回答

---

## 📖 概述

### 什么是知识库增强？

知识库增强（RAG - Retrieval Augmented Generation）是一种让 AI 能够访问**你的服务器专属知识**的技术。

**工作原理**：
```
用户提问 → 检索相关知识片段 → 将知识注入提示词 → LLM 生成回答
```

**传统 AI vs 知识库增强 AI**：

| 特性 | 传统 AI | 知识库增强 AI |
|------|---------|--------------|
| 知识来源 | 训练数据（通用） | 你的服务器文档 + 训练数据 |
| 准确性 | 可能过时或不准确 | 基于最新服务器规则 |
| 定制化 | 无法了解你的服务器 | 完全了解你的服务器 |
| 维护成本 | 需重新训练模型 | 只需更新文档 |

## 🚀 快速开始

### 1. 创建知识库目录

```bash
plugins/Kilacraft-AI/knowledge/
```

### 2. 添加知识文档

创建 Markdown 或纯文本文件：

```
knowledge/
├── server_rules.md          # 服务器规则
├── beginner_guide.md        # 新手指南
├── faq.md                   # 常见问题
├── economy_system.md        # 经济系统说明
└── events.md                # 活动介绍
```

### 3. 加载知识库

```
/kilacraft knowledge reload
```

### 4. 测试效果

```
玩家: 怎么圈地？
AI: 你可以使用 /claim 命令来圈定你的领地。需要至少 10 个金币。
    （基于知识库中的"服务器规则"文档）
```

- ✅ **纯文本 (.txt)** - 简单场景

### Markdown 最佳实践

#### 1. 使用清晰的标题结构

```
# 一级标题（文档主题）

## 二级标题（主要分类）

### 三级标题（子分类）

#### 四级标题（详细内容）
```

**示例**：
```
# 服务器规则

## 基本规则

### 禁止事项
1. 禁止作弊
2. 禁止辱骂

### 允许事项
1. 友好交流
2. 合作建造

## 经济系统

### 赚钱方式
- 挖矿
- 钓鱼
- 交易

### 禁止行为
- 刷钱漏洞
- 诈骗
```

**为什么重要？**
- AI 会根据标题智能分段
- 检索时可以精确定位到相关章节
- 提高回答的准确性和相关性

## 🔍 检索机制详解

### 智能分段算法

Kilacraft-AI 使用**基于 Markdown 标题的智能分段**：

```
# 服务器规则                    ← 分段点 1

## 基本规则                      ← 分段点 2

### 禁止事项                     ← 分段点 3
1. 禁止作弊
2. 禁止辱骂

### 允许事项                     ← 分段点 4
1. 友好交流
2. 合作建造

## 经济系统                      ← 分段点 5
...
```

**每个分段包含**：
- 完整的内容文本
- 标题层级信息（用于权重计算）
- 文件名和路径（用于溯源）

---

### 综合评分算法

当用户提问时,系统会对所有分段进行评分:

#### 级别 1：完整问题匹配（最高优先级）

如果分段内容直接包含用户的问题：

```
用户提问: "怎么圈地？"

匹配分段:
"""
## 如何圈地？

你可以使用 /claim 命令来圈定你的领地...
"""

得分: 100 分（完全匹配）
```

---

#### 级别 2：BM25 关键词评分

使用 HanLP TF-IDF 算法提取关键词，然后使用 BM25 公式计算每个关键词的匹配度：

```
用户提问: "我想建个农场，需要什么？"

关键词提取: ["农场", "需要"]

匹配分段:
"""
## 农场建造指南

建造农场需要准备：
1. 种子
2. 水
3. 工具
"""

```

**中文分词优化**：
- 使用 **HanLP TF-IDF 算法**处理中文
- 智能过滤停用词（"的"、"了"、"吗"等）
- TF-IDF自动提取最重要关键词,过滤无意义词
- 支持同义词扩展

---

#### 级别 3：标题匹配（基础优先级）

如果内容和关键词都不匹配，则匹配标题：

```
用户提问: "规则是什么？"

匹配分段标题:
- "# 服务器规则" → 得分 50 分
- "## 基本规则" → 得分 45 分
```

---

**评分公式**：

#### 级别 1：完整问题匹配
- 如果分段内容包含完整用户问题：+50.0 分

#### 级别 2：BM25 关键词评分
```
基础分 = TF × (k1 + 1) / (TF + k1 × lengthNorm)
```

**BM25 公式组成部分**：
- **TF（词频）**：关键词在文档中出现的次数
- **IDF（逆文档频率）**：由 HanLP TF-IDF 自动计算
- **lengthNorm（文档长度归一化）**：`1 - b + b × (docLength / avgDocLength)`
- **k1（词频饱和参数）**：默认 1.5（建议 1.2-2.0）
- **b（文档长度归一化参数）**：默认 0.75（建议 0.5-0.8）

**计算公式**：
```
关键词得分 = TF × (k1 + 1) / (TF + k1 × lengthNorm)
```

**关键词权重**：
- 长度 ≥ 4：权重 3
- 长度 = 3：权重 2
- 长度 < 3：权重 1

#### 级别 3：位置加权
如果关键词出现在标题（以`#`开头的行）中：
```
关键词得分 += 15.0 × 关键词权重
```

#### 级别 4：精确匹配奖励
如果有任何关键词在文档中出现：
```
总分 += 10.0
```

#### 最终得分
```
总分 = 50.0 (完整匹配,如果有) 
    + 所有关键词的BM25得分
    + 所有标题加权的BM25得分
    + 10.0 (精确匹配奖励,如果有)
```

---

**示例计算**：

用户提问："圈地方法"
提取关键词：["圈地", "方法"]
文档片段：
```
## 如何圈地？

1. 准备 10 个金币
2. 站在想要圈地的位置
3. 执行 `/claim`
```

评分过程：
1. 完整问题匹配：× (不包含完整问题)
2. 关键词"圈地"（长度=2，权重=1）：
   - TF=3, 得分 = 3 × 1.5 / (3 + 1.5 × 0.6) = 2.25 × 1 = 2.25
3. 关键词"方法"（长度=2，权重=1）：
   - TF=2, 得分 = 2 × 1.5 / (2 + 1.5 × 0.6) = 1.5 × 1 = 1.5
4. 位置加权：检查"## 如何圈地？"是否包含"圈地"和"方法" → 只包含"圈地"
   - 标题中的关键词额外加分：+15.0 × 1 = +15.0
5. 精确匹配：√ (有任一关键词在文档中出现)
   
最终得分 ≈ 2.25 + 1.5 + 15.0 + 0 = 18.75
```

### 缓存优化

**首次检索**：
1. 遍历所有知识文件
2. 解析并分段(智能分段策略)
3. 计算相似度得分
4. 缓存分段结果
5. 返回 Top-K 结果

**二次检索（相同文件）**：
- 直接从缓存读取分段
- 速度提升约 **70%**

**缓存失效条件**：
- 执行 `/kilacraft knowledge reload`
- 服务器重启

## ⚙️ 配置选项

### 配置文件位置

```
plugins/Kilacraft-AI/config.yml
```

### 相关配置项

```
knowledge:
  enabled: true                    # 是否启用知识库
  max_relevant_chunks: 3           # 每次检索返回的最大片段数
  
  segment:
    max_size: 500                  # 每个片段最大字符数
    min_size: 25                   # 每个片段最小字符数
    overlap: 30                    # 片段重叠字符数
  
  keywords:
    top_k: 10                      # 每次提取的关键词数量
  
  bm25:
    k1: 1.5                        # 词频饱和参数(1.2-2.0)
    b: 0.75                        # 文档长度归一化参数(0.5-0.8)
  
  custom_dictionary:
    enabled: true                    # 是否启用自定义词典
    words:
      - "圈地"
      - "领地"
      - "红石"
```

### 配置说明

#### `max_relevant_chunks`

控制每次检索返回的知识片段数量：

| 值 | 效果 | 适用场景 |
|----|------|---------|
| 1-2 | 精准回答 | 简单问题 |
| 3-5 | 平衡 | 大多数场景（推荐） |
| 6+ | 全面但冗长 | 复杂问题 |

**注意**：过多的片段会增加 token 消耗和响应时间。

---

#### `segment.max_size` / `min_size` / `overlap`

控制知识库分段策略：

| 配置项 | 效果 | 默认值 |
|-------|------|--------|
| max_size | 单个片段最大字符数 | 500 |
| min_size | 单个片段最小字符数 | 25 |
| overlap | 片段重叠字符数(保持上下文) | 30 |

**分段策略**：
1. 优先按 Markdown 标题分段
2. 其次按段落(空行)分段
3. 最后按固定大小分段

---

#### `keywords.top_k`

控制每次提取的关键词数量：

| 值 | 效果 |
|----|------|
| 5-10 | 平衡(推荐) |
| 10-15 | 更多召回,但可能引入噪音 |
| 15+ | 召回率高,但精确度下降 |

---

#### `bm25.k1` / `b`

BM25 算法参数：

| 参数 | 效果 | 建议值 |
|------|------|--------|
| k1 | 词频饱和点(越大越重视词频) | 1.2-2.0 |
| b | 文档长度归一化(越大越惩罚长文档) | 0.5-0.8 |

---

#### `custom_dictionary.enabled` / `words`

自定义词典,用于添加专业术语和服务器特有词汇：

```
custom_dictionary:
  enabled: true
  words:
    - "圈地"
    - "领地"
    - "红石"
    - "刷怪塔"
```

**好处**：提升中文分词准确性,改善检索效果。

## 🐛 故障排除

### Q1: AI 没有使用知识库内容？

**检查清单**：

1. **确认知识库已启用**
   ```yaml
   knowledge:
     enabled: true
   ```

2. **确认文件已加载**
   ```
   /kilacraft knowledge reload
   ```
   查看控制台输出：
   ```
   [Kilacraft-AI] 已加载 5 个知识文件，共 128 个分段
   ```

3. **检查文件格式**
   - 文件扩展名必须是 `.md` 或 `.txt`
   - 文件编码必须是 UTF-8

4. **调整返回片段数**
   ```yaml
   max_relevant_chunks: 5  # 增加返回数量
   ```

5. **开启调试模式**
   在 config.yml 中设置 `settings.debug_mode: true`
   查看检索日志，确认是否有匹配结果。

---

### Q2: 检索结果不准确？

**优化方法**：

1. **改进文档结构**
   - 使用清晰的标题
   - 添加关键词和同义词
   - 提供具体示例

2. **增加相关内容密度**
   ````
   ## 圈地/领地/保护
   
   圈地（领地、保护区域）是...
   
   相关命令：
   - /claim（圈地）
   - /unclaim（取消圈地）
   ```

3. **调整返回片段数**
   ```yaml
   max_relevant_chunks: 5  # 增加返回数量
   ```

4. **检查分段质量**
   开启调试模式，查看实际分段内容是否合理。

---

### Q3: 检索速度慢？

**优化方法**：

1. **减少知识库规模**
   - 删除过时内容
   - 合并相似文档
   - 控制单个文件大小

2. **使用 SSD 存储**
   知识库文件存储在 SSD 上可以显著提升读取速度。

---

### Q4: 中文检索效果差？

**已知问题**：
- 中文分词比英文复杂
- 同义词和近义词较多

**解决方案**：

1. **在文档中添加同义词**
   ````
   ## 圈地/领地/保护区域/Claim
   
   圈地（也称为领地、保护区域、Claim）是...
   ```

2. **调整返回片段数**
   ```yaml
   max_relevant_chunks: 5  # 增加返回数量
   ```

3. **增加关键词密度**
   在文档中多次提及核心概念的不同表达方式。

4. **提供常见问题列表**
   ````
   ## 常见问题
   
   Q: 怎么圈地？
   Q: 如何保护我的建筑？
   Q: 领地怎么弄？
   
   A: 使用 /claim 命令...
   ```
