# Kilacraft-AI - 知识库增强指南

> **版本**: v1.4.0  
> **说明**: 本文档详细介绍如何使用 RAG（检索增强生成）技术，让 AI 基于你的服务器文档提供准确回答

---

## 📖 概述

### 什么是知识库增强？

知识库增强（RAG - Retrieval Augmented Generation）是一种让 AI 能够访问**你的服务器专属知识**的技术。

**工作原理**：
```
用户提问 → 检索相关知识片段 → 将知识注入提示词 → LLM 生成回答
```

**传统 AI vs 知识库增强 AI**：

| 特性 | 传统 AI | 知识库增强 AI |
|------|---------|--------------|
| 知识来源 | 训练数据（通用） | 你的服务器文档 + 训练数据 |
| 准确性 | 可能过时或不准确 | 基于最新服务器规则 |
| 定制化 | 无法了解你的服务器 | 完全了解你的服务器 |
| 维护成本 | 需重新训练模型 | 只需更新文档 |

## 🚀 快速开始

### 1. 创建知识库目录

```bash
plugins/Kilacraft-AI/knowledge/
```

### 2. 添加知识文档

创建 Markdown 或纯文本文件：

```
knowledge/
├── server_rules.md          # 服务器规则
├── beginner_guide.md        # 新手指南
├── faq.md                   # 常见问题
├── economy_system.md        # 经济系统说明
└── events.md                # 活动介绍
```

### 3. 加载知识库

```
/kilacraft knowledge reload
```

### 4. 测试效果

```
玩家: 怎么圈地？
AI: 你可以使用 /claim 命令来圈定你的领地。需要至少 10 个金币。
    （基于知识库中的"服务器规则"文档）
```

## 📝 文档编写规范

### 支持的格式

- ✅ **Markdown (.md)** - 推荐，支持标题分段
- ✅ **纯文本 (.txt)** - 简单场景

### Markdown 最佳实践

#### 1. 使用清晰的标题结构

```markdown
# 一级标题（文档主题）

## 二级标题（主要分类）

### 三级标题（子分类）

#### 四级标题（详细内容）
```

**示例**：
```markdown
# 服务器规则

## 基本规则

### 禁止事项
1. 禁止作弊
2. 禁止辱骂

### 允许事项
1. 友好交流
2. 合作建造

## 经济系统

### 赚钱方式
- 挖矿
- 钓鱼
- 交易

### 禁止行为
- 刷钱漏洞
- 诈骗
```

**为什么重要？**
- AI 会根据标题智能分段
- 检索时可以精确定位到相关章节
- 提高回答的准确性和相关性

---

#### 2. 使用列表和结构化内容

✅ **推荐**：
```markdown
## 如何获得钻石？

你可以通过以下方式获得钻石：

1. **挖矿**：在 Y=-58 到 Y=-53 层挖掘
2. **探索**：寻找洞穴和峡谷中的暴露矿脉

**提示**：使用幸运附魔可以增加掉落量！
```

❌ **避免**：
```markdown
## 如何获得钻石

你可以挖矿或者去洞穴找或者和别人换或者做任务，对了用幸运附魔更好。
```

## 🔍 检索机制详解

### 智能分段算法

Kilacraft-AI 使用**基于 Markdown 标题的智能分段**：

```markdown
# 服务器规则                    ← 分段点 1

## 基本规则                      ← 分段点 2

### 禁止事项                     ← 分段点 3
1. 禁止作弊
2. 禁止辱骂

### 允许事项                     ← 分段点 4
1. 友好交流
2. 合作建造

## 经济系统                      ← 分段点 5
...
```

**每个分段包含**：
- 完整的内容文本
- 标题层级信息（用于权重计算）
- 文件名和路径（用于溯源）

---

### 三级评分机制

当用户提问时，系统会对所有分段进行评分：

#### 级别 1：完整问题匹配（最高优先级）

如果分段内容直接包含用户的问题：

```
用户提问: "怎么圈地？"

匹配分段:
"""
## 如何圈地？

你可以使用 /claim 命令来圈定你的领地...
"""

得分: 100 分（完全匹配）
```

---

#### 级别 2：关键词匹配（中等优先级）

提取用户问题中的关键词，计算匹配度：

```
用户提问: "我想建个农场，需要什么？"

关键词提取: ["农场", "需要"]

匹配分段:
"""
## 农场建造指南

建造农场需要准备：
1. 种子
2. 水
3. 工具
"""

得分: 75 分（关键词匹配）
```

**中文分词优化**：
- 使用 n-gram 算法处理中文
- 智能过滤停用词（"的"、"了"、"吗"等）
- 支持同义词扩展

---

#### 级别 3：标题匹配（基础优先级）

如果内容和关键词都不匹配，则匹配标题：

```
用户提问: "规则是什么？"

匹配分段标题:
- "# 服务器规则" → 得分 50 分
- "## 基本规则" → 得分 45 分
```

---

### 缓存优化

**首次检索**：
1. 遍历所有知识文件
2. 解析并分段
3. 计算相似度得分
4. 返回 Top-K 结果

**二次检索（相同问题）**：
- 直接从缓存读取结果
- 速度提升约 **70%**

**缓存失效条件**：
- 执行 `/kilacraft knowledge reload`
- 知识文件被修改
- 服务器重启

## ⚙️ 配置选项

### 配置文件位置

```
plugins/Kilacraft-AI/config.yml
```

### 相关配置项

```yaml
knowledge_base:
  enabled: true                  # 是否启用知识库
  directory: "knowledge"         # 知识库目录路径
  max_chunks_per_query: 3        # 每次检索返回的最大片段数
  similarity_threshold: 0.3      # 相似度阈值（0.0-1.0）
  cache_enabled: true            # 是否启用缓存
  cache_ttl_seconds: 3600        # 缓存过期时间（秒）
  debug_mode: false              # 调试模式（输出详细日志）
```

### 配置说明

#### `max_chunks_per_query`

控制每次检索返回的知识片段数量：

| 值 | 效果 | 适用场景 |
|----|------|---------|
| 1-2 | 精准回答 | 简单问题 |
| 3-5 | 平衡 | 大多数场景（推荐） |
| 6+ | 全面但冗长 | 复杂问题 |

**注意**：过多的片段会增加 token 消耗和响应时间。

---

#### `similarity_threshold`

设置最低相似度阈值，过滤不相关的结果：

| 值 | 效果 |
|----|------|
| 0.1-0.3 | 宽松，返回更多结果 |
| 0.3-0.5 | 平衡（推荐） |
| 0.5-0.8 | 严格，只返回高度相关结果 |
| 0.8+ | 极严格，可能无结果 |

---

#### `cache_ttl_seconds`

缓存过期时间：

```yaml
cache_ttl_seconds: 3600   # 1 小时
# 或
cache_ttl_seconds: 86400  # 24 小时
# 或
cache_ttl_seconds: 0      # 永不过期（不推荐）
```

---

#### `debug_mode`

开启调试模式后，控制台会输出详细的检索信息：

```yaml
debug_mode: true
```

**输出示例**：

## 🎯 高级用法

### 1. 多语言知识库

为不同语言的玩家提供专属知识库：

```
knowledge/
├── zh_CN/              # 简体中文
│   ├── rules.md
│   └── guide.md
├── en_US/              # 英文
│   ├── rules.md
│   └── guide.md
└── ja_JP/              # 日文
    ├── rules.md
    └── guide.md
```

在代码中根据玩家语言动态加载：

```java
String lang = player.getLocale(); // "zh_CN", "en_US", etc.
String knowledgeDir = "knowledge/" + lang;
```

---

### 2. 权限控制的知识库

为不同玩家组提供不同的知识内容：

```
knowledge/
├── public/             # 所有人可见
│   ├── rules.md
│   └── faq.md
├── vip/                # VIP 专属
│   ├── vip_benefits.md
│   └── exclusive_items.md
└── staff/              # 管理员专属
    ├── admin_commands.md
    └── moderation_guide.md
```

实现方式：
```java
if (player.hasPermission("group.vip")) {
    loadKnowledge("knowledge/vip/");
}
```

---

### 3. 时效性知识

为限时活动创建临时知识库：

```
knowledge/
├── permanent/          # 永久知识
│   └── rules.md
└── seasonal/           # 季节性知识
    ├── christmas_2026.md
    └── halloween_2026.md
```

活动结束后删除或归档：
```bash
mv knowledge/seasonal/christmas_2026.md knowledge/archive/
/kilacraft knowledge reload
```

---

### 4. 版本化知识库

跟踪知识库的变更历史：

```
knowledge/
├── current/            # 当前版本
│   └── rules.md
├── v1.0/               # 历史版本
│   └── rules.md
└── v2.0/
    └── rules.md
```

回滚到旧版本：
```bash
cp knowledge/v1.0/rules.md knowledge/current/rules.md
/kilacraft knowledge reload
```

## 🐛 故障排除

### Q1: AI 没有使用知识库内容？

**检查清单**：

1. **确认知识库已启用**
   ```yaml
   knowledge_base:
     enabled: true
   ```

2. **确认文件已加载**
   ```
   /kilacraft knowledge reload
   ```
   查看控制台输出：
   ```
   [Kilacraft-AI] 已加载 5 个知识文件，共 128 个分段
   ```

3. **检查文件格式**
   - 文件扩展名必须是 `.md` 或 `.txt`
   - 文件编码必须是 UTF-8

4. **调整相似度阈值**
   ```yaml
   similarity_threshold: 0.2  # 降低阈值
   ```

5. **开启调试模式**
   ```yaml
   debug_mode: true
   ```
   查看检索日志，确认是否有匹配结果。

---

### Q2: 检索结果不准确？

**优化方法**：

1. **改进文档结构**
   - 使用清晰的标题
   - 添加关键词和同义词
   - 提供具体示例

2. **增加相关内容密度**
   ```markdown
   ## 圈地/领地/保护
   
   圈地（领地、保护区域）是...
   
   相关命令：
   - /claim（圈地）
   - /unclaim（取消圈地）
   ```

3. **调整返回片段数**
   ```yaml
   max_chunks_per_query: 5  # 增加返回数量
   ```

4. **检查分段质量**
   开启调试模式，查看实际分段内容是否合理。

---

### Q3: 检索速度慢？

**优化方法**：

1. **启用缓存**
   ```yaml
   cache_enabled: true
   cache_ttl_seconds: 3600
   ```

2. **减少知识库规模**
   - 删除过时内容
   - 合并相似文档
   - 控制单个文件大小

3. **使用 SSD 存储**
   知识库文件存储在 SSD 上可以显著提升读取速度。

4. **预加载常用知识**
   在插件启动时预加载热点内容到内存。

---

### Q4: 中文检索效果差？

**已知问题**：
- 中文分词比英文复杂
- 同义词和近义词较多

**解决方案**：

1. **在文档中添加同义词**
   ```markdown
   ## 圈地/领地/保护区域/Claim
   
   圈地（也称为领地、保护区域、Claim）是...
   ```

2. **使用更低的相似度阈值**
   ```yaml
   similarity_threshold: 0.2
   ```

3. **增加关键词密度**
   在文档中多次提及核心概念的不同表达方式。

4. **提供常见问题列表**
   ```markdown
   ## 常见问题
   
   Q: 怎么圈地？
   Q: 如何保护我的建筑？
   Q: 领地怎么弄？
   
   A: 使用 /claim 命令...
   ```
