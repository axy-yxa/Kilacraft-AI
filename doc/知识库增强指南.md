## 💡 核心理念：知识库质量决定一切

> **“Garbage In, Garbage Out”（垃圾进，垃圾出）**  
> —— George Fuechsel，计算机科学家

在 RAG（检索增强生成）技术中，**知识库文档的质量直接决定了检索质量和召回率**：

- ✅ **高质量知识库** → 精确检索 → 准确回答 → **节省 Token**
- ❌ **低质量知识库** → 混乱检索 → 错误回答 → **浪费 Token**

### 为什么质量影响 Token 消耗？

| 知识库质量 | 检索结果 | Token 消耗 | 回答质量 |
|----------|---------|-----------|--------|
| **高质量**（结构清晰、内容准确） | 1-2 个精确片段 | ~200-300 tokens | 准确、简洁 |
| **中等质量**（有结构但不够精确） | 3-5 个相关片段 | ~500-800 tokens | 基本准确 |
| **低质量**（混乱、重复、冗长） | 5+ 个噪声片段 | ~1000+ tokens | 可能错误 |

**结论**：花时间优化知识库文档，不仅能提高 AI 回答的准确性，还能**显著降低 API 调用成本**！

### 高质量知识库的关键特征

1. ✅ **结构清晰**：使用 Markdown 标题分级，便于智能分段
2. ✅ **内容精确**：每个章节聚焦一个主题，避免内容混杂
3. ✅ **语言简洁**：用简洁的语言表达，避免冗长啰嗦
4. ✅ **关键词丰富**：包含用户可能使用的关键词和同义词
5. ✅ **格式规范**：使用列表、表格等结构化内容
6. ✅ **定期维护**：及时更新过时内容，删除冗余信息

## 📖 概述

### 什么是知识库增强？

知识库增强（RAG - Retrieval Augmented Generation）是一种让 AI 能够访问**你的服务器专属知识**的技术。

**工作原理**：
```
用户提问 → 检索相关知识片段 → 将知识注入提示词 → LLM 生成回答
```

**传统 AI vs 知识库增强 AI**：

| 特性 | 传统 AI | 知识库增强 AI |
|------|---------|--------------|
| 知识来源 | 训练数据（通用） | 你的服务器文档 + 训练数据 |
| 准确性 | 可能过时或不准确 | 基于最新服务器规则 |
| 定制化 | 无法了解你的服务器 | 完全了解你的服务器 |
| 维护成本 | 需重新训练模型 | 只需更新文档 |

## 🔍 检索机制详解

### 智能分段算法

Kilacraft-AI 使用**三层降级分段策略**，自动选择最适合的分段方式：

```
策略 1: 按 Markdown 标题分割（优先）
  ↓ 如果没有标题
策略 2: 按段落分割（空行分隔）
  ↓ 如果没有空行
策略 3: 按固定大小分割（兜底）
```

---

#### 策略 1：按 Markdown 标题分割 ⭐ **推荐**

**触发条件**：文档中包含 `#` 到 `######` 标题

**分段规则**：
- 从标题开始，读取后续内容
- 遇到**空行**或**下一个标题**时停止
- 包含标题 + 紧跟的内容（不含空行后的内容）
- 如果单个片段超过 `max_size (500字符)` → 自动降级为策略 2

**案例 1：标准命令文档**

```markdown
# 服务器命令

## /back - 返回死亡点
当你死亡后，可以使用此命令快速回到死亡位置。
这在探索洞穴、打boss时非常有用。
冷却时间：30秒
权限：无

## /spawn - 传送回主城
传送回服务器的主城区域。
所有玩家都可以使用。
```

**分段结果**：
```
片段 1: "# 服务器命令" (10字符)
片段 2: "## /back - 返回死亡点\n当你死亡后...冷却时间：30秒\n权限：无" (80字符) ✅
片段 3: "## /spawn - 传送回主城\n传送回服务器...所有玩家都可以使用。" (70字符) ✅
```

**✅ 优势**：
- 每个命令保持完整上下文
- 标题信息保留（BM25 标题加权 +15 分）
- 语义完整性最好

---

**案例 2：超长命令说明（>500字符）**

```markdown
## /back - 返回死亡点
当你死亡后，可以使用此命令快速回到死亡位置。
这在探索洞穴、打boss时非常有用。
（中间省略 400 字符详细说明...）
注意事项：
1. 冷却时间 30 秒
2. 战斗状态无法使用
3. 需要站立不动 3 秒
```

**分段结果**：
```
策略 1 尝试：单个片段 600 字符 > max_size (500)
  ↓ 触发策略 2
策略 2 按段落分割：
  片段 1: "## /back - 返回死亡点\n当你死亡后..." (约 300 字符) ✅
  片段 2: "注意事项：\n1. 冷却时间 30 秒..." (约 200 字符) ✅
```

**⚠️ 注意**：
- 标题只在片段 1，片段 2 失去标题加权
- 用户搜索"back 冷却时间"可能匹配到片段 2，但没有标题加分

---

#### 策略 2：按段落分割 📄 **备选**

**触发条件**：Markdown 分割失败或文档无标题

**分段规则**：
- 以**空行**（`\n\n`）作为分隔符
- 每个段落必须 `≥ min_size (25字符)`
- 小于 25 字符的段落会被**过滤掉**

**案例 3：TXT 格式命令文档（有空行）**

```txt
/back - 返回死亡点
当你死亡后，可以使用此命令。
冷却时间：30秒

/spawn - 传送回主城
传送回服务器的主城区域。
所有玩家都可以使用。
```

**分段结果**：
```
片段 1: "/back - 返回死亡点\n当你死亡后...冷却时间：30秒" (60字符) ✅
片段 2: "/spawn - 传送回主城\n传送回服务器...所有玩家都可以使用。" (70字符) ✅
```

**✅ 优势**：
- 按空行自然分段
- 保持命令完整性

**⚠️ 注意**：
- 没有标题标记 → 失去 BM25 标题加权（-15 分）
- 命令名在普通文本中，权重较低

---

**案例 4：TXT 格式命令文档（无空行）** ❌ **严重问题**

```txt
/back - 返回死亡点
当你死亡后，可以使用此命令。
冷却时间：30秒
/spawn - 传送回主城
传送回服务器的主城区域。
/home - 回家
传送到你设置的家。
```

**分段结果**：
```
策略 1：无 # 标题 → 失败
策略 2：无空行 → 整个文档作为一个段落 (150字符)
  ↓ 150 < max_size (500)
  结果：1 个大片段包含所有命令 ❌
```

**❌ 问题**：
- 所有命令混在一起
- BM25 检索时无法区分
- 用户搜索"back"会返回包含所有命令的大片段

**✅ 正确做法**：命令之间必须加空行！

---

**案例 5：短命令列表（< 25字符）** ⚠️ **会被过滤**

```txt
/back 回死亡点

/spawn 回主城

/home 回家

/money 查余额
```

**分段结果**：
```
片段 1: "/back 回死亡点" (11字符) ❌ 小于 25 字符，被过滤
片段 2: "/spawn 回主城" (13字符) ❌ 小于 25 字符，被过滤
片段 3: "/home 回家" (9字符) ❌ 小于 25 字符，被过滤
片段 4: "/money 查余额" (13字符) ❌ 小于 25 字符，被过滤

结果：0 个片段 ❌ 所有命令都被过滤！
```

**⚠️ 重要说明**：
- `min_size: 25` 配置会过滤掉太短的片段
- **一行一个命令的简洁格式会被过滤！**
- 必须添加详细说明，使每个命令片段 ≥ 25 字符

**✅ 正确做法**：
```txt
/back - 返回死亡点
当你死亡后，使用此命令快速回到死亡位置。
冷却时间：30秒。

/spawn - 传送回主城
传送回服务器的主城区域，所有玩家都可以使用。
主城是安全区域，禁止PVP。
```

#### 策略 3：按固定大小分割 🔧 **兜底**

**触发条件**：段落分割也失败（无空行的连续文本）

**分段规则**：
- 每段最大 `max_size (500字符)`
- 优先在**句子边界**（`.` `!` `?` `\n`）切割
- 相邻片段有 `overlap (30字符)` 重叠

**案例 6：连续文本（无标题、无空行）**

```txt

```

**分段结果**：
```
策略 1：无标题 → 失败
策略 2：无空行 → 整个作为 1 段 (100字符)
策略 3：100 < max_size (500) → 不触发
结果：1 个片段 (100字符)
```

### 分段配置参数详解

```yaml
knowledge:
  segment:
    max_size: 500    # 单个片段最大字符数
    min_size: 25     # 单个片段最小字符数（小于此值会被过滤）
    overlap: 30      # 片段重叠字符数（仅策略3使用）
```

**参数说明**：

| 参数 | 作用 | 默认值 | 影响 |
|------|------|--------|------|
| `max_size` | 限制单个片段的最大长度 | 500 | 防止片段过长影响检索精度 |
| `min_size` | 过滤太短的无意义片段 | 25 | **⚠️ 短命令列表会被过滤！** |
| `overlap` | 保持相邻片段的上下文 | 30 | 仅策略3使用，避免信息丢失 |

**⚠️ `min_size` 重要提醒**：

如果你使用以下格式编写命令文档：

```txt
❌ 错误：一行一个命令（会被过滤）
/back 回死亡点
/spawn 回主城
/home 回家
```

必须改为：

```txt
✅ 正确：添加详细说明（≥ 25字符）
/back - 返回死亡点
当你死亡后，使用此命令快速回到死亡位置。
冷却时间：30秒。

/spawn - 传送回主城
传送回服务器的主城区域，所有玩家都可以使用。
```

或者使用 Markdown 格式：

```markdown

### 综合评分算法

当用户提问时,系统会对所有分段进行评分:

#### 级别 1：完整问题匹配（最高优先级）

如果分段内容直接包含用户的问题：

```
用户提问: "怎么圈地？"

匹配分段:
"""
## 如何圈地？

你可以使用 /claim 命令来圈定你的领地...
"""

得分: 100 分（完全匹配）
```

---

#### 级别 2：BM25 关键词评分

使用 HanLP TF-IDF 算法提取关键词，然后使用 BM25 公式计算每个关键词的匹配度：

```
用户提问: "我想建个农场，需要什么？"

关键词提取: ["农场", "需要"]

匹配分段:
"""
## 农场建造指南

建造农场需要准备：
1. 种子
2. 水
3. 工具
"""

```

**中文分词优化（v1.4.3 更新）**：
- **三层关键词提取策略**：原始查询 + 分词结果 + TF-IDF 关键词，兼容短文本和长文档
- **单字查询优化**：支持"弓"、"剑"等单字物品名查询，通过自定义词典和停用词检查
- **智能过滤停用词**：过滤"的"、"了"、"吗"等无意义词汇
- **TF-IDF自动提取重要关键词**：基于 HanLP 算法计算关键词权重
- **内置词汇表支持**：从 JAR 包的 internal/vocabulary/ 目录加载内置词汇，与自定义词汇合并自动去重

---

#### 级别 3：标题匹配（基础优先级）

如果内容和关键词都不匹配，则匹配标题：

```
用户提问: "规则是什么？"

匹配分段标题:
- "# 服务器规则" → 得分 50 分
- "## 基本规则" → 得分 45 分
```

---

**评分公式**：

#### 级别 1：完整问题匹配
- 如果分段内容包含完整用户问题：+50.0 分

#### 级别 2：BM25 关键词评分
```
基础分 = TF × (k1 + 1) / (TF + k1 × lengthNorm)
```

**BM25 公式组成部分**：
- **TF（词频）**：关键词在文档中出现的次数
- **IDF（逆文档频率）**：由 HanLP TF-IDF 自动计算
- **lengthNorm（文档长度归一化）**：`1 - b + b × (docLength / avgDocLength)`
- **k1（词频饱和参数）**：默认 1.5（建议 1.2-2.0）
- **b（文档长度归一化参数）**：默认 0.75（建议 0.5-0.8）

**计算公式**：
```
关键词得分 = TF × (k1 + 1) / (TF + k1 × lengthNorm)
```

**关键词权重**：
- 长度 ≥ 4：权重 3
- 长度 = 3：权重 2
- 长度 < 3：权重 1

#### 级别 3：位置加权
如果关键词出现在标题（以`#`开头的行）中：
```
关键词得分 += 15.0 × 关键词权重
```

#### 级别 4：精确匹配奖励
如果有任何关键词在文档中出现：
```
总分 += 10.0
```

#### 最终得分
```
总分 = 50.0 (完整匹配,如果有) 
    + 所有关键词的BM25得分
    + 所有标题加权的BM25得分
    + 10.0 (精确匹配奖励,如果有)
```

---

**示例计算**：

用户提问："圈地方法"
提取关键词：["圈地", "方法"]
文档片段：
```
## 如何圈地？

1. 准备 10 个金币
2. 站在想要圈地的位置
3. 执行 `/claim`
```

评分过程：
1. 完整问题匹配：× (不包含完整问题)
2. 关键词"圈地"（长度=2，权重=1）：
   - TF=3, 得分 = 3 × 1.5 / (3 + 1.5 × 0.6) = 2.25 × 1 = 2.25
3. 关键词"方法"（长度=2，权重=1）：
   - TF=2, 得分 = 2 × 1.5 / (2 + 1.5 × 0.6) = 1.5 × 1 = 1.5
4. 位置加权：检查"## 如何圈地？"是否包含"圈地"和"方法" → 只包含"圈地"
   - 标题中的关键词额外加分：+15.0 × 1 = +15.0
5. 精确匹配：√ (有任一关键词在文档中出现)
   
最终得分 ≈ 2.25 + 1.5 + 15.0 + 0 = 18.75

**首次检索**：
1. 遍历所有知识文件

4. 缓存分段结果

## ⚙️ 配置选项

### 配置文件位置

```
plugins/Kilacraft-AI/config.yml
```

### 相关配置项

```
knowledge:
  enabled: true                    # 是否启用知识库
  max_relevant_chunks: 3           # 每次检索返回的最大片段数
  
  segment:
    max_size: 500                  # 每个片段最大字符数
    min_size: 25                   # 每个片段最小字符数
    overlap: 30                    # 片段重叠字符数
  
  keywords:
    top_k: 10                      # 每次提取的关键词数量
  
  bm25:
    k1: 1.5                        # 词频饱和参数(1.2-2.0)
    b: 0.75                        # 文档长度归一化参数(0.5-0.8)
  
  custom_dictionary:
    enabled: true                    # 是否启用自定义词典
    words:
      - "圈地"
      - "领地"
      - "红石"
```

### 配置说明

#### `max_relevant_chunks`

控制每次检索返回的知识片段数量：

| 值 | 效果 | 适用场景 |
|----|------|---------|
| 1-2 | 精准回答 | 简单问题 |
| 3-5 | 平衡 | 大多数场景（推荐） |
| 6+ | 全面但冗长 | 复杂问题 |

**注意**：过多的片段会增加 token 消耗和响应时间。

---

#### `segment.max_size` / `min_size` / `overlap`

**详细说明请参考上面的“分段配置参数详解”章节**。

简要说明：
- `max_size`: 单个片段最大字符数（默认 500）
- `min_size`: 单个片段最小字符数（默认 25，**小于此值的片段会被过滤**）
- `overlap`: 片段重叠字符数（默认 30，仅策略 3 使用）

---

#### `keywords.top_k`

控制每次提取的关键词数量：

| 值 | 效果 |
|----|------|
| 5-10 | 平衡(推荐) |
| 10-15 | 更多召回,但可能引入噪音 |
| 15+ | 召回率高,但精确度下降 |

---

#### `bm25.k1` / `b`

BM25 算法参数：

| 参数 | 效果 | 建议值 |
|------|------|--------|
| k1 | 词频饱和点(越大越重视词频) | 1.2-2.0 |
| b | 文档长度归一化(越大越惩罚长文档) | 0.5-0.8 |

---

#### `custom_dictionary.enabled` / `words`

自定义词典,用于添加专业术语和服务器特有词汇：

```
custom_dictionary:
  enabled: true
  words:
    - "圈地"
    - "领地"
    - "红石"
    - "刷怪塔"
```

**好处**：提升中文分词准确性,改善检索效果。

## 🐛 故障排除

### Q1: AI 没有使用知识库内容？

**检查清单**：

1. **确认知识库已启用**
   ```yaml
   knowledge:
     enabled: true
   ```

2. **确认文件已加载**
   ```
   /kilacraft knowledge reload
   ```
   查看控制台输出：
   ```
   [Kilacraft-AI] 已加载 5 个知识文件，共 128 个分段
   ```

3. **检查文件格式**
   - 文件扩展名必须是 `.md` 或 `.txt`
   - 文件编码必须是 UTF-8

4. **调整返回片段数**
   ```yaml
   max_relevant_chunks: 5  # 增加返回数量
   ```

5. **开启调试模式**
   在 config.yml 中设置 `settings.debug_mode: true`
   查看检索日志，确认是否有匹配结果。

---

### Q2: 检索结果不准确？

**优化方法**：

1. **改进文档结构**
   - 使用清晰的标题
   - 添加关键词和同义词
   - 提供具体示例

2. **增加相关内容密度**
   ````
   ## 圈地/领地/保护
   
   圈地（领地、保护区域）是...
   
   相关命令：
   - /claim（圈地）
   - /unclaim（取消圈地）
   ```

3. **调整返回片段数**
   ```yaml
   max_relevant_chunks: 5  # 增加返回数量
   ```

4. **检查分段质量**
   开启调试模式，查看实际分段内容是否合理。

---

### Q3: 检索速度慢？

**优化方法**：

1. **减少知识库规模**
   - 删除过时内容
   - 合并相似文档
   - 控制单个文件大小

2. **使用 SSD 存储**
   知识库文件存储在 SSD 上可以显著提升读取速度。

---

### Q4: 中文检索效果差？

**已知问题**：
- 中文分词比英文复杂
- 同义词和近义词较多

**解决方案**：

1. **在文档中添加同义词**
   ````
   ## 圈地/领地/保护区域/Claim
   
   圈地（也称为领地、保护区域、Claim）是...
   ```

2. **调整返回片段数**
   ```yaml
   max_relevant_chunks: 5  # 增加返回数量
   ```

3. **增加关键词密度**
   在文档中多次提及核心概念的不同表达方式。

4. **提供常见问题列表**
   ````
   ## 常见问题
   
   Q: 怎么圈地？
   Q: 如何保护我的建筑？
   Q: 领地怎么弄？
   
   A: 使用 /claim 命令...
   ```
