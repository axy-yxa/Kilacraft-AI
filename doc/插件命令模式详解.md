## 概述

插件命令模式是 Kilacraft-AI 为**第三方插件集成**设计的专用接口，允许其他插件通过控制台以指定的人格调用 AI。

**核心设计理念：**
> 插件命令模式不是给服主手动执行的命令，而是**供第三方插件在代码或配置中调用**的 API 接口。

**主要应用场景：**
- 🤖 **NPC 智能对话**：让 MythicMobs NPC 拥有不同性格，与玩家自然交流
- 🎮 **自定义交互**：根据插件逻辑动态生成符合人设的 AI 回复
- 🔗 **回调命令集成**：AI 完成后自动执行指定命令，无缝嵌入第三方插件

## 核心概念

### 三种交互模式对比

| 模式 | 触发方式 | Agent 能力 | 知识库检索 | 回调机制 | 典型场景 |
|------|---------|-----------|-----------|---------|----------|
| **ChatListener** | `@ai` 关键词 / 连续对话 | ✅ 启用 | ✅ 智能注入 | ❌ 不需要 | 玩家主动交互 |
| **KilacraftCommand** | `/kilacraft <消息>` | ✅ 启用 | ✅ 智能注入 | ❌ 不需要 | 服主/管理员查询 |
| **Plugin Command** | `/kilacraft plugins ...` | ❌ 禁用 | ✅ 普通检索 | ✅ **必须** | 第三方插件集成 |

### 为什么插件命令模式不启用 Agent 能力？

1. **回调机制要求纯文本输出**
   ```java
   executeCallback(callbackCommand, fullResponse);
   //                          ^^^^^^^^^^^^
   //                          必须是 String 类型！
   ```
   - Agent 路径可能返回结构化数据（Map、List 等）
   - 无法保证最终结果是可序列化的纯文本
   - 回调命令需要明确的文本内容作为参数

2. **职责定位不同**
   - ChatListener/KilacraftCommand: "帮我做某事"（任务执行）
   - Plugin command: "给我一段 AI 生成的文本"（内容创作）

3. **性能考虑**
   - 插件命令可能被频繁调用（如 MythicMobs 占位符）
   - 避免不必要的意图识别开销（约 2-5 秒）
   - 直接普通 AI 调用更快（约 1-3 秒）

4. **语义清晰**
   - `/kilacraft plugins default Hello UUID` = "用默认人格回答'你好'"
   - 不是"帮我执行某些任务"

## 命令格式与参数

### 基本格式

```
/kilacraft plugins <人格名称> <消息内容> <玩家 UUID> [回调命令...]
```

### 参数详解

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `<人格名称>` | String | ✅ | 在 `personalities.yml` 中定义的人格名称 |
| `<消息内容>` | String | ✅ | 要发送给 AI 的消息（支持空格） |
| `<玩家 UUID>` | UUID | ✅ | 目标玩家的 UUID（标准格式） |
| `[回调命令...]` | String | ❌ | AI 完成后自动执行的命令（支持 `{response}` 占位符） |

### 重要特性

- 🔒 **仅限控制台执行**：玩家无法直接使用此命令（防止滥用）
- 🌐 **独立历史记录**：每个 `UUID_人格` 组合有独立的历史记录，互不干扰
- ⏱️ **专用冷却时间**：使用 `plugins_cooldown_seconds` 配置（默认 3 秒）
- 🌍 **世界限制检查**：如果目标玩家在线，会检查是否在禁止的世界
- 💬 **回调命令支持**：AI 完成后自动执行指定命令，`{response}` 会被替换为实际回复

## 回调机制详解

### 回调工作流程

```
第三方插件触发事件
    ↓
执行控制台命令：/kilacraft plugins <人格> <问题> <玩家UUID> [回调命令]
    ↓
Kilacraft-AI 以指定人格生成回复（异步，2-5秒）
    ↓
AI 完成后自动执行回调命令（以控制台身份）
    ↓
你的插件接收回调命令，处理 AI 回复
    ↓
缓存立即删除（一次性消费）
```

### 回调命令格式

**带占位符的回调命令：**
```
myplugin handle_ai {response} 玩家名
```

**执行时会自动替换：**
```
myplugin handle_ai "嘻嘻~ 服务器规则很简单哦！✨..." 玩家名
```

### 回调命令解析注意事项

如果你的回调命令参数包含空格，需要正确解析：

```java
@Override
public boolean onCommand(CommandSender sender, Command command, String label, String[] args) {
    if (!command.getName().equalsIgnoreCase("myplugin")) {
        return false;
    }
    
    if (args.length == 0 || !args[0].equals("handle_ai")) {
        return false;
    }
    
    // 最后一个参数是玩家名称
    String playerName = args[args.length - 1];
    
    // 中间的所有参数是 AI 回复（合并）
    StringBuilder responseBuilder = new StringBuilder();
    for (int i = 1; i < args.length - 1; i++) {
        if (i > 1) responseBuilder.append(" ");
        responseBuilder.append(args[i]);
    }
    String aiResponse = responseBuilder.toString();
    
    // 获取玩家并显示消息
    Player player = Bukkit.getPlayer(playerName);
    if (player != null && player.isOnline()) {
        player.sendMessage("§e[NPC 狐狸] §f" + aiResponse);
    }
    
    return true;
}
```

## 回调方法优化最佳实践

### ⚠️ 关键优化：避免阻塞主线程

**问题：**
当第三方插件在回调命令中执行耗时操作时，会阻塞 Minecraft 主线程，导致服务器卡顿。

**解决方案：**
在回调命令处理器中**立即返回**，然后异步执行业务逻辑。

### ✅ 推荐的回调处理方法

```java
@Override
public boolean onCommand(CommandSender sender, Command command, String label, String[] args) {
    if (!command.getName().equalsIgnoreCase("myplugin") || args.length == 0) {
        return false;
    }
    
    if (args[0].equals("handle_ai")) {
        // 解析参数
        String playerName = args[args.length - 1];
        StringBuilder responseBuilder = new StringBuilder();
        for (int i = 1; i < args.length - 1; i++) {
            if (i > 1) responseBuilder.append(" ");
            responseBuilder.append(args[i]);
        }
        String aiResponse = responseBuilder.toString();
        
        // ✅ 关键：立即返回，告诉 Bukkit 命令已完成
        // 这样不会阻塞主线程
        
        // 异步执行业务逻辑
        Bukkit.getScheduler().runTaskAsynchronously(this, () -> {
            // 在这里执行耗时操作
            // 例如：数据库查询、API 调用、复杂计算等
            
            // 如果需要发送消息给玩家，切换回主线程
            Bukkit.getScheduler().runTask(this, () -> {
                Player player = Bukkit.getPlayer(playerName);
                if (player != null && player.isOnline()) {
                    player.sendMessage("§e[NPC 狐狸] §f" + aiResponse);
                }
            });
        });
        
        // ✅ 立即返回 true，表示命令已成功处理
        return true;
    }
    
    return false;
}
```

### ❌ 不推荐的做法

```java
@Override
public boolean onCommand(CommandSender sender, Command command, String label, String[] args) {
    if (args[0].equals("handle_ai")) {
        // ❌ 错误：在主线程执行耗时操作
        Thread.sleep(5000);  // 模拟耗时操作
        
        // ❌ 这会阻塞主线程 5 秒，导致服务器卡顿！
        Player player = Bukkit.getPlayer(playerName);
        player.sendMessage("§e[NPC 狐狸] §f" + aiResponse);
        
        return true;
    }
    return false;
}
```

### 为什么要这样做？

1. **Kilacraft-AI 的超时保护只监控主线程命令执行时间**
   ```yaml
   plugin_command:
     callback_timeout_seconds: 3  # 监控主线程命令执行时间
   ```

2. **如果回调命令在主线程执行超过 3 秒**
   - Kilacraft-AI 会强制中断命令执行
   - 记录警告日志：`[WARN] 回调命令执行超时 (3s)，已强制中断`
   - 但这**不会**中断你已经启动的异步任务

3. **异步处理的优势**
   - ✅ 不阻塞主线程，服务器流畅运行
   - ✅ 可以执行任意耗时的业务逻辑
   - ✅ Kilacraft-AI 的超时保护不会影响你的异步任务
   - ✅ 需要在适当时机切换回主线程发送消息

### 完整的异步处理示例

```java
@Override
public boolean onCommand(CommandSender sender, Command command, String label, String[] args) {
    if (!command.getName().equalsIgnoreCase("myplugin") || args.length == 0) {
        return false;
    }
    
    if (args[0].equals("handle_ai")) {
        // 1. 快速解析参数（在主线程）
        String playerName = args[args.length - 1];
        StringBuilder responseBuilder = new StringBuilder();
        for (int i = 1; i < args.length - 1; i++) {
            if (i > 1) responseBuilder.append(" ");
            responseBuilder.append(args[i]);
        }
        String aiResponse = responseBuilder.toString();
        
        // 2. 立即返回，不阻塞主线程
        Bukkit.getScheduler().runTaskAsynchronously(this, () -> {
            try {
                // 3. 异步执行耗时操作
                // 示例：查询数据库获取玩家额外信息
                String extraInfo = queryDatabase(playerName);
                
                // 示例：调用外部 API
                String translated = callTranslationAPI(aiResponse);
                
                // 4. 准备最终消息
                String finalMessage = String.format("§e[NPC 狐狸] §f%s\n§7额外信息: %s", 
                    translated, extraInfo);
                
                // 5. 切换回主线程发送消息
                Bukkit.getScheduler().runTask(this, () -> {
                    Player player = Bukkit.getPlayer(playerName);
                    if (player != null && player.isOnline()) {
                        player.sendMessage(finalMessage);
                        
                        // 可以播放音效、粒子效果等
                        player.playSound(player.getLocation(), Sound.ENTITY_EXPERIENCE_ORB_PICKUP, 1.0f, 1.0f);
                    }
                });
                
            } catch (Exception e) {
                // 6. 异常处理（在异步线程）
                getLogger().severe("处理 AI 回复时出错: " + e.getMessage());
                e.printStackTrace();
                
                // 通知玩家出错了（切换回主线程）
                Bukkit.getScheduler().runTask(this, () -> {
                    Player player = Bukkit.getPlayer(playerName);
                    if (player != null && player.isOnline()) {
                        player.sendMessage("§c抱歉，处理请求时出错了，请稍后再试。");
                    }
                });
            }
        });
        
        // 7. 立即返回 true
        return true;
    }
    
    return false;
}

// 模拟数据库查询
private String queryDatabase(String playerName) {
    // 这里是耗时操作，在异步线程执行
    try {
        Thread.sleep(1000);  // 模拟数据库查询
        return "玩家等级: 50";
    } catch (InterruptedException e) {
        return "未知";
    }
}

// 模拟 API 调用
private String callTranslationAPI(String text) {
    // 这里是耗时操作，在异步线程执行
    try {
        Thread.sleep(500);  // 模拟 API 调用
        return text;  // 实际应该调用翻译 API
    } catch (InterruptedException e) {
        return text;
    }
}
```

```java
public void onNPCInteract(PlayerInteractEntityEvent event) {
    Player player = event.getPlayer();
    Entity npc = event.getRightClicked();
    
    // 检查是否是特定的 NPC
    if (npc.getCustomName() != null && npc.getCustomName().equals("狐狸 NPC")) {
        // 构建回调命令

            "myplugin handle_ai %s %s", 
            "{response}",  // 占位符，会被替换为实际回复

        );
        
        // 调用 Kilacraft-AI 插件命令
        Bukkit.dispatchCommand(Bukkit.getConsoleSender(), String.format(
            "kilacraft plugins 狐狸 服务器的规则是什么 %s %s",
            player.getUniqueId().toString(),
            callbackCommand
        ));
        
        player.sendMessage("§e狐狸正在思考...");
    }
}
```

## 历史记录隔离机制

### 隔离规则

每个 `UUID_人格` 组合有独立的历史记录：

```
玩家 A + 狐狸人格 → 独立历史 1
玩家 A + 严厉教师人格 → 独立历史 2
玩家 B + 狐狸人格 → 独立历史 3
```

### 优势

1. **人格一致性**：同一玩家与不同人格对话时，上下文不会混淆
2. **隐私保护**：不同玩家的对话历史完全隔离
3. **灵活切换**：玩家可以随时切换人格，不影响其他对话

### 配置

历史记录数量在 `config.yml` 中配置：

```yaml
settings:
  max_history: 10  # 每个 UUID_人格 组合最多保存 10 轮对话
```

### 清除历史

```
# 清除特定玩家的所有历史
/kilacraft clear <玩家名>

# 玩家自己清除历史
/kilacraft clear
```

## 常见问题

### Q1: 为什么不推荐使用不带回调的命令？

**A:** 不带回调的命令会将 AI 回复缓存在内存中，但没有标准方法获取回复。这种方式：
- ❌ 没有官方支持的获取方式
- ❌ 需要自行开发轮询或占位符机制
- ❌ 可能导致内存泄漏（缓存未清理）

**推荐做法：** 始终使用回调命令，这是唯一官方支持的集成方式。

### Q2: 回调命令执行超时怎么办？

**A:** 如果看到以下日志：
```
[WARN] 回调命令执行超时 (3s)，已强制中断。命令: myplugin handle_ai ...
```

这表示：
- ✅ 主线程的命令执行被中断（正常行为）
- ⚠️ 如果你的插件使用异步处理，异步任务仍在运行
- 💡 这不是错误，是预期行为

**解决方案：**
1. 确保回调命令处理器立即返回（参考上方最佳实践）
2. 将耗时操作放在异步线程执行
3. 如需调整超时时间，修改 `config.yml`：
   ```yaml
   plugin_command:
     callback_timeout_seconds: 5  # 增加到 5 秒
   ```

### Q3: 如何调试插件命令模式？

**A:** 开启调试模式：
```yaml
# config.yml
settings:
  debug_mode: true
```

控制台会输出详细的执行日志，包括：
- 命令接收
- 人格加载
- AI 请求发送
- 回调命令执行

### Q4: 支持离线玩家吗？

**A:** 
- ✅ **支持**：UUID 对应的玩家可以是离线状态
- ⚠️ **限制**：如果玩家离线，无法发送消息
- 💡 **建议**：在回调处理器中检查玩家在线状态

```java
Player player = Bukkit.getPlayer(playerName);
if (player != null && player.isOnline()) {
    player.sendMessage(aiResponse);
} else {
    // 玩家离线，可以将消息存入数据库，等上线后发送
    saveOfflineMessage(playerName, aiResponse);
}
```

### Q5: 如何测试插件命令模式？

**A:** 可以在控制台手动测试：

```
# 测试基本功能
```
