## BUG-001：挂机任务完成后 AI 仍认为任务在运行

**状态**：🔄 已确认 / 待修复  
**优先级**：中  
**影响版本**：v1.4.3 及之前所有版本  
**影响范围**：所有使用挂机任务功能的玩家

---

### 问题描述

当玩家创建了一个挂机任务（如"帮我盯着 Hub 上线"），任务完成（Hub 上线并已通知玩家）后，玩家在后续对话中与 AI 闲聊时，AI 仍然基于历史对话认为任务正在运行中，给出错误回复。

**实际表现**：
```
[19:36] 玩家: /ai 帮我盯着Hub，他上线了就报告他的位置
[19:36] AI: 搞定！我已经帮你设置好挂机任务了，只要 Hub 一上线，我就会立刻通知你他的位置。
[19:38] [系统] Hub 上线 → 挂机任务完成 → AI 已通知玩家 Hub 的位置
[19:39] 玩家: /ai 晚上好啊
[19:39] AI: 晚上好！Hub还没上线，不过我已经在持续监控了。  ← ❌ 错误！Hub 已上线，任务已完成
```

**正确行为**：AI 应该知道挂机任务已经完成，回复中不应再提及"还在监控"。

---

### 复现步骤

1. 玩家 A 创建挂机任务：`/ai 帮我盯着[玩家B]，他上线了告诉我`
2. 等待目标玩家 B 上线，挂机任务触发并完成，玩家 A 收到通知
3. 玩家 A 继续对话：`/ai 晚上好啊`
4. AI 回复中错误地认为任务仍在运行

---

### 根因分析

#### 调用链路分析

```
玩家发送消息 "晚上好啊"
  ↓
AIRequestHandler.handleNormalAIRequest()
  ↓
GenericLLMProvider.processRequest()
  → 使用 configManager.getSystemPrompt() 作为系统提示词
  → 注入对话历史（包含创建挂机任务的历史）
  ↓
LLM 看到的上下文：
  System: "你是一个 Minecraft 游戏助手..."
  History[1] (user): "帮我盯着Hub，他上线了就报告他的位置"     ← 保留了创建任务的历史
  History[2] (assistant): "搞定！我已经帮你设置好挂机任务了..."  ← 保留了 AI 的回复
  User: "晚上好啊"
  ↓
LLM 推理：历史中提到了"挂机任务"，没有"任务完成"的信息 → 回复"还在监控"
```

#### 核心原因

1. **挂机任务是异步延迟执行的**：任务可能在创建后几分钟甚至几小时才触发
2. **对话历史中没有"任务完成"的记录**：任务完成通知是独立发送的，不写入对话历史
3. **系统提示词中不包含实时状态**：`system_prompt` 是静态配置，不包含挂机任务的当前状态
4. **LLM 只能依赖历史对话推断状态**：历史中有"创建任务"但没有"任务完成"，导致推断错误

---

### 约束条件

在设计修复方案时，必须满足以下约束：

| 约束 | 原因 |
|------|------|
| ❌ **不能延迟添加对话上下文** | 挂机任务是异步的，可能在多轮对话后才完成。延迟插入"任务完成"消息会污染对话历史，打断正常对话流程 |
| ❌ **不能删除历史中的挂机任务对话** | 如果删除"帮我盯着Hub"的历史记录，后续对话中玩家说"取消那个任务"或"换个人盯"时，AI 无法理解上下文，导致意图识别失败 |
| ❌ **不能修改已保存的历史记录** | 对话历史是玩家的真实交互记录，修改会导致其他不可预知的问题 |

---

### 计划修复方案：系统提示词动态注入 AFK 任务状态

**核心思路**：和知识库检索（RAG）一样，在每次 LLM 请求构建系统提示词时，**动态查询**玩家的挂机任务当前状态，作为系统提示词的附加信息注入。这个信息**不保存到对话历史**，只在当前请求的 system message 中生效。

#### 技术设计

**注入位置**：`GenericLLMProvider.processRequestWithCustomSystemPrompt()` 方法中，在构建系统提示词时追加 AFK 状态信息。

**注入内容示例**：

任务运行中时：
```
你是一个 Minecraft 游戏助手...

【挂机任务状态】
当前正在运行挂机任务：监视玩家 Hub 上线（任务创建于 19:36）
```

任务已完成时：
```
你是一个 Minecraft 游戏助手...

【挂机任务状态】
当前没有运行中的挂机任务。（如果之前的对话中提到过挂机任务，说明该任务已经完成或已取消）
```

无任务时（从未创建过）：
```
你是一个 Minecraft 游戏助手...
（不注入任何额外信息）
```

#### 实现要点

1. **在 `GenericLLMProvider` 中**：构建 `systemPrompt` 时，追加 AFK 任务状态信息
   ```java
   // 伪代码
   String systemPrompt = customSystemPrompt.replace("{player}", playerName);
   
   // 动态注入 AFK 任务状态（仅对玩家请求）
   if (playerName != null && !"IntentRecognizer".equals(playerName)) {
       String afkStatus = buildAfkStatus(playerName);
       if (afkStatus != null) {
           systemPrompt += "\n\n" + afkStatus;
       }
   }
   ```

2. **状态查询**：通过 `plugin.getAfkTaskManager().getTask(uuid)` 获取当前任务
   - 有任务 → 注入运行中的任务信息
   - 无任务但历史中曾提及 → 注入"任务已完成或取消"
   - 无任务且未提及 → 不注入

3. **优化判断**：只在对话历史中出现过挂机任务相关关键词时才注入"任务已完成"的提示，避免无关对话中注入多余信息

#### 优势

- ✅ **不污染对话历史** - 系统提示词每次动态生成，不保存到 history
- ✅ **不影响意图识别** - 历史中的挂机任务对话完整保留
- ✅ **实时准确** - 每次请求都检查最新状态
- ✅ **轻量** - 只需一次 `manager.hasTask(uuid)` 查询，无性能开销
- ✅ **对非玩家请求无影响** - 控制台请求和意图识别请求跳过注入
- ✅ **与现有架构一致** - 类似知识库检索的注入方式，架构风格统一

#### 风险评估

- ⚠️ **Token 消耗增加**：每次请求多注入约 50-100 个 token 的 AFK 状态信息
- ⚠️ **判断"历史中是否提及挂机任务"需要遍历历史**：可以通过简单的关键词匹配实现
