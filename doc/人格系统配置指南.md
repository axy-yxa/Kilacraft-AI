# Kilacraft-AI - 人格系统配置指南

> **版本**: v1.4.5  
> **说明**: 本文档详细介绍如何配置和管理多个 AI 人格，让每个 AI 助手都有独特的性格和风格

---

## 📖 概述

Kilacraft-AI 的**人格系统**允许你为服务器创建多个不同风格的 AI 助手。每个人格都是独立的提示词配置，通过 `/kilacraft plugins` 命令使用。

### 核心特性

- 🎭 **多个人格**：可配置多个不同性格的 NPC
- 🔧 **公共提示词**：所有人格共享的基础设定
- 🔄 **动态切换**：通过命令参数指定使用哪个人格
- 📝 **占位符支持**：支持 `{player}` 自动替换为玩家名称

### 应用场景

| 场景 | 推荐人格 |
|------|---------|
| 新手引导 | 温柔耐心的导师型人格 |
| 技术支持 | 专业严谨的技术专家人格 |
| 娱乐互动 | 幽默风趣的聊天伙伴人格 |
| 角色扮演 | 符合服务器剧情的 NPC 人格 |

---

## 🔧 配置文件结构

### 文件位置

```
plugins/Kilacraft-AI/personalities.yml
```

### 基本结构

```yaml
# 公共提示词（所有人格共享的基础提示词）
common_prompt: "你是一个 Minecraft 游戏的 NPC，需要满足玩家的常见要求。"

# 人格配置（人格名称 -> 提示词）
严厉教师: "你是一位严厉的 Minecraft 教师，正在教导玩家 {player}。\n你对学生的要求很高，说话简洁直接，但会耐心解答问题。\n专注于教授游戏机制、红石电路和建筑技巧。"

冒险伙伴: "你是玩家 {player} 的忠实冒险伙伴，性格开朗幽默。\n你喜欢分享探险故事，提供战斗建议，推荐装备搭配，总是鼓励玩家勇敢探索。"

图书管理员: "你是一位博学的图书管理员，正在为冒险者 {player} 提供知识服务。\n你说话文雅，喜欢引用古籍，精通 Minecraft 的历史、生物特性、矿物分布和各种冷知识。"

奸商: "你是一个精明的 Minecraft 商人，正在和顾客 {player} 交谈。\n你说话圆滑，总想推销自己的商品，对经济系统和交易价格了如指掌，时不时会开个玩笑。"
```

**重要说明**：
- 配置文件采用**扁平结构**，每个人格直接作为顶级键
- `common_prompt` 是特殊键，会被自动排除在人格列表之外
- 人格名称可以是中文或英文
- 提示词中可以使用 `{player}` 占位符，运行时会自动替换为实际玩家名称

## 🎭 人格配置详解

### 1. 公共提示词（common_prompt）

**作用**：所有人格共享的基础设定，会在每个人格的提示词前面自动添加。

```yaml
common_prompt: "你是一个 Minecraft 游戏的 NPC，需要满足玩家的常见要求。"
```

**最佳实践**：
- 设置通用的行为准则
- 定义基本的对话规范
- 避免重复写在每个人格中

**示例**：
```yaml
common_prompt: |
  你是一个 Minecraft 服务器的智能助手。
  
  ## 基本要求
  - 使用简体中文交流
  - 回答简洁明了
  - 不提供作弊方法
  - 保持友好态度
```

---

### 2. 人格提示词

每个人格就是一个简单的键值对：**人格名称 -> 提示词字符串**。

#### 基础格式

```yaml
人格名称: "提示词内容"
```

#### 多行提示词（推荐）

使用 YAML 的多行字符串语法（`|` 或 `|-`）：

```yaml
严厉教师: |
  你是一位严厉的 Minecraft 教师，正在教导玩家 {player}。
  
  ## 你的特点
  - 对学生要求很高
  - 说话简洁直接
  - 耐心解答问题
  
  ## 专业领域
  - 游戏机制
  - 红石电路
  - 建筑技巧
```

#### 单行提示词

适合简短的人格设定：

```yaml
幽默伙伴: "你是玩家 {player} 的搞笑朋友，喜欢讲笑话和玩梗。"
```

---

### 3. 占位符支持

人格提示词中可以使用 `{player}` 占位符，系统会自动替换为当前玩家的名称。

```yaml
冒险伙伴: |
  你是玩家 {player} 的忠实冒险伙伴。
  
  当与 {player} 对话时：
  - 称呼他为"{player}"
  - 分享探险经验给他
  - 为他推荐装备搭配
```

**运行时效果**：
如果玩家名称是 `Steve`，则 `{player}` 会被替换为 `Steve`。

## 🔄 使用人格

### 通过插件命令使用

人格系统仅在**插件命令模式**下使用，通过 `/kilacraft plugins` 命令调用：

```bash
/kilacraft plugins <message> <player_uuid> [personality] [callback_command]
```

**参数说明**：
- `<message>`：玩家的消息内容
- `<player_uuid>`：玩家的 UUID
- `[personality]`：可选，人格名称（默认使用第一个人格）
- `[callback_command]`：可选，回调命令

**示例**：

```bash
# 使用默认人格
/kilacraft plugins "你好" 069a79f4-44e9-4726-a5be-fca90e38aaf5

# 指定使用"严厉教师"人格
/kilacraft plugins "怎么制作红石火把？" 069a79f4-44e9-4726-a5be-fca90e38aaf5 严厉教师

# 指定人格并设置回调命令
/kilacraft plugins "钻石在哪里？" 069a79f4-44e9-4726-a5be-fca90e38aaf5 新手导师 "tell {player} {response}"
```

## 💡 编写提示词的最佳实践

### ✅ 推荐做法

**1. 角色定位清晰**

```yaml
新手导师: |
  你是"小萌"，一位经验丰富的老玩家，专门帮助新人 {player}。
  
  你的特点：
  - 耐心细致，从不嘲笑新手问题
  - 善于用简单易懂的语言解释
  - 总是给予鼓励和肯定
```

**2. 明确行为准则**

```yaml
技术专家: |
  你是 TechBot，专业的技术问题解答者。
  
  ## 回答原则
  - 优先提供准确的 technical 信息
  - 如果不确定，诚实告知
  - 引用官方文档或权威来源
  - 不使用模糊表述
```

**3. 定义语言风格**

```yaml
幽默伙伴: |
  你是"逗比君"，超级幽默的聊天机器人。
  
  ## 说话风格
  - 大量使用网络流行语
  - 经常讲笑话和段子
  - 适当使用表情符号 😊
  - 自嘲是常态
```

**4. 利用占位符增强代入感**

```yaml
冒险伙伴: |
  你是玩家 {player} 的忠实冒险伙伴。
  
  在与 {player} 对话时：
  - 称呼他为"{player}"
  - 分享你的探险故事给 {player}
  - 为 {player} 推荐装备搭配
```

---

### ❌ 避免的做法

**1. 过于简略**

```yaml
# ❌ 不推荐：缺乏具体指导
助手: "你是一个友好的助手"

# ✅ 推荐：详细说明
助手: |
  你是友善的 AI 助手，正在帮助玩家 {player}。
  
  你的特点：
  - 热情友好，乐于助人
  - 回答简洁明了
  - 主动提供相关建议
```

**2. 包含矛盾指令**

```yaml
# ❌ 不推荐：自相矛盾
助手: |
  你要非常幽默
  但也要非常严肃

# ✅ 推荐：明确场景
助手: |
  平时保持幽默风趣的风格
  但在回答 serious 技术问题时切换为专业严谨模式
```

**3. 硬编码具体数据**

```yaml
# ❌ 不推荐：版本更新后会过时
助手: "钻石在 Y=-58 层"

# ✅ 推荐：引导查询知识库
助手: |
  对于具体的游戏数据（如矿物分布），请引导玩家查询最新的游戏 Wiki
  或建议使用游戏内命令查询
```

## 🐛 常见问题

### Q1: 修改配置后没有生效？

**解决方法**：
1. 确认文件格式正确（YAML 格式）
2. 执行 `/kilacraft personalities reload` 重新加载
3. 查看控制台是否有错误信息
4. 检查人格名称是否与命令中使用的完全一致（包括大小写）

---

### Q2: 如何测试人格效果？

**方法**：
1. 使用测试账号登录
2. 通过插件命令调用不同人格
3. 发送各种类型的消息测试响应
4. 检查是否符合预期风格

**测试示例**：
```bash
# 测试严厉教师
/kilacraft plugins "怎么制作工作台？" <UUID> 严厉教师

# 测试幽默伙伴
/kilacraft plugins "给我讲个笑话" <UUID> 幽默伙伴

# 测试技术专家
/kilacraft plugins "红石中继器有什么用？" <UUID> 技术专家
```

---

### Q3: 人格太多会影响性能吗？

**答案**：不会。

- 人格配置只在启动或重载时加载到内存
- 每次对话只使用一个人格的提示词
- 内存占用极小（每个人格约几百字节到几 KB）
- 可以安全创建数十个人格

---

### Q4: 如何让人格更了解服务器？

**方案**：结合知识库系统。

1. 在 `common_prompt` 中添加通用指引：
```yaml
common_prompt: |
  你是 Minecraft 服务器的 AI 助手。
  
  如果玩家询问服务器特定信息（如规则、活动、特色玩法）：
  - 优先从知识库中检索相关信息
  - 如果知识库中没有，诚实告知并建议联系管理员
```

2. 在知识库中添加服务器专属文档（见[知识库增强指南](./知识库增强指南)）

---

### Q5: 人格名称可以使用英文吗？

**答案**：可以。

人格名称支持中文和英文，只要保持一致即可：

```yaml
# 中文名称
新手导师: "..."
技术专家: "..."

# 英文名称
mentor: "..."
tech_expert: "..."
```

使用时对应传入：
```bash
/kilacraft plugins "Hello" <UUID> mentor
```

---

### Q6: 如何删除某个人格？

**方法**：
1. 打开 `personalities.yml`
2. 删除对应的人格配置行
3. 执行 `/kilacraft personalities reload`

**注意**：不要删除 `common_prompt`，否则所有人格都会失去基础设定。
