# Kilacraft-AI - 人格系统配置指南

> **版本**: v1.4.0  
> **说明**: 本文档详细介绍如何配置和管理多个 AI 人格，让每个 AI 助手都有独特的性格和风格

---

## 📖 概述

Kilacraft-AI 的**人格系统**允许你为服务器创建多个不同风格的 AI 助手。每个人格都有独立的：

- 🎭 **角色设定**：背景故事、性格特征
- 💬 **语言风格**：说话方式、用词习惯
- 🎨 **回复偏好**：幽默程度、正式程度
- 🔧 **功能权限**：可访问的技能范围

### 应用场景

| 场景 | 推荐人格 |
|------|---------|
| 新手引导 | 温柔耐心的导师型人格 |
| 技术支持 | 专业严谨的技术专家人格 |
| 娱乐互动 | 幽默风趣的聊天伙伴人格 |
| 角色扮演 | 符合服务器剧情的 NPC 人格 |

---

## 🔧 配置文件结构

### 文件位置

```
plugins/Kilacraft-AI/personalities.yml
```

### 基本结构

```yaml
personalities:
  # 人格 ID（唯一标识符）
  default:
    name: "默认助手"
    description: "友善且专业的 AI 助手"
    
    # 系统提示词（核心配置）
    system_prompt: |
      你是 Kilacraft-AI，一个友善且专业的 Minecraft 服务器助手。
      
      ## 你的特点
      - 热情友好，乐于助人
      - 回答简洁明了，避免冗长
      - 使用中文交流，适当使用表情符号
      
      ## 行为准则
      - 如果不知道答案，诚实告知
      - 不提供游戏作弊方法
      - 保持积极正面的态度
    
    # 语言风格配置
    style:
      tone: "friendly"        # 语气：friendly/professional/humorous/serious
      formality: "casual"     # 正式程度：formal/casual
      emoji_usage: true       # 是否使用表情符号
      max_response_length: 500  # 最大回复长度（字符数）
    
    # 功能配置
    features:
      enable_knowledge_base: true   # 启用知识库检索
      enable_bukkit_api: true       # 启用 Bukkit API
      enable_market_query: true     # 启用市场查询
      allowed_skills: []            # 允许的技能列表（空表示全部）
    
    # 外观配置（可选）
    appearance:
      prefix: "[AI]"                # 消息前缀
      color: "&b"                   # 消息颜色（Minecraft 颜色代码）
  
  # 第二个人格示例
  mentor:
    name: "新手导师"
    description: "耐心指导新玩家的导师"
    # ... 更多配置
```

## 🎭 人格配置详解

### 1. 基础信息

#### `name`（人格名称）

显示给玩家的名称，建议使用简洁易记的名称。

```yaml
name: "小助手"
name: "技术专家"
name: "冒险向导"
```

#### `description`（人格描述）

简短描述人格的特点，用于管理员识别。

```yaml
description: "友善且专业的 AI 助手，适合日常对话"
description: "严谨的技术专家，擅长解答游戏机制问题"
```

---

### 2. 系统提示词（system_prompt）

**这是人格系统的核心！** 系统提示词决定了 AI 的行为模式、语言风格和知识范围。

#### 最佳实践

✅ **推荐做法**：

```yaml
system_prompt: |
  你是 Minecraft 服务器的新手导师"小萌"。
  
  ## 你的身份
  - 你是一位经验丰富的老玩家，乐于帮助新人
  - 你对游戏机制了如指掌，尤其是生存技巧
  - 你说话温和耐心，从不嘲笑新手的问题
  
  ## 回答风格
  - 使用简单易懂的语言，避免专业术语
  - 多用鼓励性话语："很棒的问题！"、"加油！"
  - 适当使用表情符号增加亲和力 😊
  
  ## 行为准则
  - 优先提供实用建议，而非理论解释
  - 如果问题复杂，分步骤讲解
  - 主动询问是否需要更详细的说明
  
  ## 禁止事项
  - 不提供作弊或漏洞利用方法
  - 不贬低其他玩家或服务器
  - 不涉及政治、宗教等敏感话题
```

❌ **避免的做法**：

```yaml
# ❌ 过于简略
system_prompt: "你是一个友好的助手"

# ❌ 包含矛盾指令
system_prompt: |
  你要非常幽默
  但也要非常严肃

# ❌ 硬编码具体数据
system_prompt: "钻石在 Y=-58 层"  # 版本更新后会过时
```

#### 高级技巧

**1. 角色代入**


**2. 专业知识领域**

```yaml
  你的专长：
  - 红石电路设计和优化

  1. 先确认他们的红石基础水平
  2. 从简单概念开始讲解
```

**3. 语言风格定制**


### 3. 语言风格配置（style）

#### `tone`（语气）

控制 AI 的整体语气风格：

| 值 | 说明 | 适用场景 |
|----|------|---------|
| `friendly` | 友好亲切 | 日常对话、新手引导 |
| `professional` | 专业正式 | 技术支持、官方公告 |
| `humorous` | 幽默风趣 | 娱乐互动、聊天机器人 |
| `serious` | 严肃认真 | 规则说明、警告提示 |
| `enthusiastic` | 热情洋溢 | 活动宣传、成就庆祝 |

```yaml
style:
  tone: "friendly"  # 推荐大多数场景
```

#### `formality`（正式程度）

| 值 | 说明 | 示例 |
|----|------|------|
| `formal` | 正式 | "您好，请问有什么可以帮助您的？" |
| `casual` | 随意 | "嗨！有啥问题尽管问～" |

```yaml
style:
  formality: "casual"  # 更适合游戏环境
```

#### `emoji_usage`（表情符号）

```yaml
style:
  emoji_usage: true   # 使用表情符号增加趣味性
  # 或
  emoji_usage: false  # 纯文本，更专业
```

#### `max_response_length`（最大回复长度）

限制单次回复的最大字符数，避免过长影响阅读体验：

```yaml
style:
  max_response_length: 500   # 适中长度
  # 或
  max_response_length: 200   # 简洁回复
  # 或
  max_response_length: 1000  # 详细解答
```

---

### 4. 功能配置（features）

#### 启用/禁用功能模块

```yaml
features:
  enable_knowledge_base: true   # 是否使用知识库增强
  enable_bukkit_api: true       # 是否允许调用 Bukkit API
  enable_market_query: true     # 是否允许查询市场
```

**应用场景**：

- **新手导师人格**：禁用市场查询，专注于教学
- **经济顾问人格**：仅启用市场查询
- **技术专家人格**：启用所有功能

#### 技能白名单

通过 `allowed_skills` 限制人格可使用的技能：

```yaml
features:
  allowed_skills:
    - "bukkit_api.get_player_health"
    - "bukkit_api.get_world_time"
    - "knowledge_base.query"
```

**未列出的技能将无法被该人格调用。**

留空表示允许所有技能：

```yaml
features:
  allowed_skills: []  # 无限制
```

---

### 5. 外观配置（appearance）

#### `prefix`（消息前缀）

```yaml
appearance:
  prefix: "[AI]"           # 标准前缀
  # 或
  prefix: "[小助手]"        # 个性化前缀
  # 或
  prefix: ""               # 无前缀
```

#### `color`（消息颜色）

使用 Minecraft 颜色代码：

```yaml
appearance:
  color: "&b"   # 青色
  # 或
  color: "&a"   # 绿色
  # 或
  color: "&e"   # 黄色
```

**常用颜色代码**：

| 代码 | 颜色 | 适用场景 |
|------|------|---------|
| `&b` | 青色 | 科技感、AI 助手 |
| `&a` | 绿色 | 友好、自然 |
| `&e` | 黄色 | 温暖、活力 |
| `&d` | 粉色 | 可爱、活泼 |
| `&9` | 蓝色 | 专业、稳重 |
| `&7` | 灰色 | 低调、中性 |

## 📋 完整配置示例

### 示例 1：默认助手

```yaml
personalities:
  default:
    name: "Kila"
    description: "友善且专业的 AI 助手"

      ## 回答原则
      1. 优先解决玩家的实际问题
      2. 如果不确定，诚实告知
      3. 主动提供相关建议
      4. 保持积极正面的态度
      
      ## 语言风格
      - 使用简体中文
      - 适当使用表情符号
      - 避免过于正式的措辞
    
    style:
      tone: "friendly"
      formality: "casual"
      emoji_usage: true
      max_response_length: 500
    
    features:
      enable_knowledge_base: true
      enable_bukkit_api: true
      enable_market_query: true
      allowed_skills: []
    
    appearance:
      prefix: "[Kila]"
      color: "&b"
```

### 示例 2：新手导师

```yaml
personalities:
  mentor:
    name: "小萌导师"
    description: "耐心指导新玩家的温柔导师"
    
    system_prompt: |
      你是"小萌"，一位经验丰富且耐心的新手导师。
      
      ## 你的使命
      帮助新玩家快速适应服务器，享受游戏乐趣。
      
      ## 你的特点
      - 极其耐心，从不嫌问题简单
      - 善于用类比和比喻解释复杂概念
      - 总是给予鼓励和肯定
      
      ## 教学风格
      1. 先了解玩家的游戏经验
      2. 从基础开始，循序渐进
      3. 提供实际操作步骤
      4. 提醒常见陷阱和注意事项
      5. 鼓励玩家多尝试
      
      ## 常用表达
      - "这是个很好的问题！"
      - "别担心，刚开始都这样～"
      - "让我一步步教你..."
      - "你已经做得很好了！继续加油！💪"
      
      ## 禁止事项
      - 不使用复杂的专业术语
      - 不一次性给出太多信息
      - 不批评玩家的错误
    
    style:
      tone: "friendly"
      formality: "casual"
      emoji_usage: true
      max_response_length: 600

      enable_knowledge_base: true
      enable_bukkit_api: true
      enable_market_query: false  # 新手不需要市场功能
      allowed_skills:
        - "bukkit_api.get_player_health"
        - "bukkit_api.get_player_location"
        - "bukkit_api.get_world_time"
        - "knowledge_base.query"
    
    appearance:
      prefix: "[小萌]"
      color: "&a"
```

## 🔄 切换人格

### 方法 1：通过命令切换

```
/kilacraft personality <personality_id>
```

**示例**：
```
/kilacraft personality mentor      # 切换到新手导师
/kilacraft personality tech_expert # 切换到技术专家
/kilacraft personality default     # 切换回默认助手
```

### 方法 2：为玩家设置默认人格

在配置文件中设置默认人格：

```yaml
agent:
  default_personality: "mentor"  # 所有新玩家默认使用导师人格
```

### 方法 3：基于权限自动分配

使用权限插件为不同玩家组分配不同人格：

```
# 新手组使用导师人格
/lp group newbie meta set kilacraft.personality mentor

# VIP 组使用专属人格
/lp group vip meta set kilacraft.personality vip_assistant
```

## 🛠️ 高级用法

### 动态人格切换

根据对话内容自动切换人格（需要自定义 Skill）：

```java
// 伪代码示例
if (message.contains("红石") || message.contains("电路")) {
    switchPersonality("tech_expert");
} else if (message.contains("笑话") || message.contains("搞笑")) {
    switchPersonality("joker");
}
```

### 人格组合

为不同功能模块指定不同人格：

```yaml
# 市场查询使用专业人格
market_query:
  personality: "economist"

# 闲聊使用幽默人格
chat:
  personality: "joker"

# 技术支持使用专家人格
technical_support:
  personality: "tech_expert"
```

### 季节性人格

根据时间或活动更换人格：

```yaml
# 圣诞节人格
```

## 📊 人格选择建议

### 根据服务器类型选择

| 服务器类型 | 推荐人格 | 原因 |
|-----------|---------|------|
| 生存服 | 新手导师 + 技术专家 | 兼顾教学和深度解答 |
| 创造服 | 建筑大师 + 红石专家 | 专注建筑和红石 |
| RPG 服 | 角色扮演 NPC | 增强沉浸感 |
| 小游戏服 | 幽默聊天伙伴 | 轻松娱乐氛围 |
| 综合服 | 默认助手（全能型） | 平衡各方面需求 |

### 根据玩家群体选择

| 玩家群体 | 推荐人格 | 原因 |
|---------|---------|------|
| 新手为主 | 耐心导师 | 降低学习门槛 |
| 老手为主 | 技术专家 | 满足深度需求 |
| 休闲玩家 | 幽默伙伴 | 轻松愉快 |
| 竞技玩家 | 专业教练 | 提供战术建议 |

## 🐛 常见问题

### Q1: 人格切换后没有生效？

**检查清单**：
1. 确认人格 ID 拼写正确
2. 执行 `/kilacraft reload` 重新加载配置
3. 查看控制台是否有 YAML 解析错误
4. 确认玩家有权限使用该人格

---

### Q2: 如何测试人格效果？

**方法**：
1. 使用测试账号登录
2. 切换到目标人格
3. 发送各种类型的消息测试响应
4. 检查是否符合预期风格

**测试用例**：
```
# 测试基础知识
```

### Q3: 人格太多会影响性能吗？

**答案**：不会。

- 人格配置只在启动时加载到内存
- 每次对话只激活一个人格
- 内存占用极小（每个人格约 1-2 KB）
- 可以安全创建数十个人格

### Q4: 如何让 AI 记住玩家偏好的人格？

**方案**：使用玩家数据持久化。

在数据库中存储：
```sql
CREATE TABLE player_preferences (
    uuid VARCHAR(36) PRIMARY KEY,
    preferred_personality VARCHAR(50)
);
```

玩家登录时自动恢复：
```java
String personality = database.getPreferredPersonality(player.getUniqueId());
if (personality != null) {
    setCurrentPersonality(player, personality);
}
```
