## v1.4.5 - Folia/lophine 线程安全兼容、全新流式输出功能、AI 响应管线重构、SIDEBAR 载体

### ✨ 新增功能
- **非合作式 Skill 安全拦截器**：Value 扫描 + 消毒机制，保护玩家数据隔离
  - 拦截器始终运行不可跳过，不依赖 Skill 的参数声明（非合作式）
  - 直接扫描 entities 中所有 Value，匹配在线玩家名则校验权限
  - 校验不通过 → 消毒（自动替换为当前玩家名），Skill 继续执行而非阻断
  - 白名单机制：config.yml 配置允许操作其他玩家的 Skill/动作
  - 事件驱动的在线玩家名缓存（PlayerJoin/Quit），异步线程安全读取
  - 前置过滤：Minecraft 玩家名正则校验，不符合格式的值直接跳过
  - 内置 Skill 白名单：cmi.send_tp_request、AFKTask.create_task、command.execute_command
- **BukkitFXSkill 音效与粒子效果**：AI 可为玩家播放音效或显示粒子效果（仅调用者听到/看到）
  - 支持 2 个动作：`play_sound`（播放音效）、`spawn_particle`（显示粒子）
  - 自然语言触发：任务完成庆祝、警告提示、氛围营造
  - YML 配置驱动，支持热重载
- **AI 回复音效功能**：AI 开始回复时自动播放提示音效，增强沉浸式体验
  - 音效与输出内容同步播放，仅触发玩家听到
  - 配置化开关：`output.sound.enabled`（默认开启），支持自定义音效/音量/音调
  - 支持普通对话/技能结果/任务结果/挂机回调全场景
- **全新流式输出功能**：LLM 响应逐字实时显示，消除等待焦虑
  - 请求发起后立即显示"生成中..."占位符，解决首字延迟问题
  - 实时显示 LLM 返回内容，支持 5 种配置化载体（CHAT/ACTION_BAR/BOSS_BAR/TITLE/SIDEBAR）
  - 流式完成后可选保留最终结果到默认载体
  - 配置化开关：`output.stream.enabled` 控制启用/禁用
- **AI 响应统一输出管线**：重构 AI 回复输出架构，支持场景级载体配置
  - 5 种输出载体：CHAT（聊天栏）、ACTION_BAR（物品栏上方）、BOSS_BAR（顶部横条）、TITLE（屏幕中央）、SIDEBAR（右侧边栏）
  - 普通对话/技能结果/任务结果/挂机回调/错误消息可独立配置载体
  - 配置即契约：选择什么载体就用什么，不会隐式降级
  - 公屏广播载体配置化：`public_reply=true` 时遵循 `default_channel` 配置
- **LLM 二次分析统一协调器**：全新中间层统一调度所有 LLM 分析输出
  - 封装分析+输出完整流程，调用方无需关心流式/非流式细节
  - 支持挂机任务回调不显示占位符，主动请求显示占位符
  - 消除重复输出逻辑，所有模块通过协调器统一调用
- **意图识别阶段知识库检索**：意图识别时启用知识库增强，提升技能识别准确率
  - 智能提取用户真实输入，排除提示词模板干扰
  - 结合服务器文档（命令说明/规则/玩法）辅助意图判断
- **Scoreboard Sidebar 输出载体**：全新右侧边栏输出方式，完美支持长文本 AI 回复
  - 支持最多 15 行，每行最多 128 字符（Minecraft 1.13+）
  - 自动分页：超过 15 行时自动拆分多页
  - 不遮挡游戏视野，适合长文本 AI 回复（200-1500字符）
  - 标题自动同步：直接使用 `ai_prefix` 配置
- **Folia/lophine 线程安全兼容**：完整支持 Folia 及其分支的区域化线程调度
  - Player 相关 API 自动在玩家所属区域线程执行
  - Spigot 端零影响，完全向后兼容
- **思考消息独立配置**：`output.thinking_channel` 可独立控制"正在思考"提示的输出载体

### 🔧 优化改进
- **内置配置文件管理优化**：封装 ConfigResourceUtil 工具类，统一所有配置文件的读取和初始化逻辑
- **日志输出统一优化**：全面使用 PluginLogger 替代分散的日志调用，结构化标签输出
- **Bukkit API 数据返回标准化**：统一所有 API 返回字段命名规范，物品名称自动翻译为中文
- **移除意图分类器**：彻底移除 BM25 意图分类器，所有请求直接进入 LLM 意图识别，提升准确率
- **Handler 架构重构**：各 Handler 直接实现 AIResponseHandler 接口，职责更清晰
- **包结构优化**：按功能重新组织代码（enums/manager/output/handler）
- **配置精简**：统一流式输出配置到 `output.stream.*`，移除冗余的 `output.broadcast.*` 和 `settings.enable_stream_output`

### ⚠️ 兼容性
- 新增 `output/` 配置段（包含 stream/default_channel/scenarios/boss_bar/title/sidebar/thinking_channel）
- 新增 SIDEBAR 输出载体
- 删除 `output.broadcast.*` 配置段（公屏广播改用 default_channel）
- 删除 `settings.enable_stream_output` 配置项（统一使用 output.stream.enabled）
- 完全向后兼容，默认配置保持 CHAT 载体

## v1.4.4 - 多步骤数组索引、CUSTOM 通用挂机任务、BM25 语义评分意图分类器、Skill 提示词优化

### ✨ 新增功能
- **多步骤任务数组索引访问**：支持 `{step_x.array_field[0].field_name}` 格式引用列表数据中的特定元素
- **CMI Skill 集成**：支持 CMI 插件的家、地标、传送、玩家信息查询（8 个 Action）
- **CUSTOM 通用条件轮询任务**：挂机任务系统新增通用自定义任务类型，支持监控任意 Skill 返回的数值条件
  - 支持 6 种比较操作符：less_than / less_than_or_equal / greater_than / greater_than_or_equal / equal / not_equal
  - 使用场景：血量监视、等级监视、余额监视等任意数值型条件监控
- **BM25 语义评分意图分类器**：零维护 Skill 索引 + LLM 意图识别两阶段架构
  - 基于 BM25 语义评分的智能预分类器，从 Skill 元数据自动构建虚拟文档索引
  - 7 步预分类：关键词短路 → 闲聊句式识别 → BM25 评分 → 祈使句加分 → 阈值判断

- **LLM 二次分析字数限制**：analysis_prompt_suffix 添加 400 字限制，防止回复过长
- **CUSTOM 任务防重入**：条件满足时先停止轮询再执行回调，防止重复触发
- **CUSTOM 任务容错性**：Skill 执行失败或超时不中断任务，继续下次轮询
- **CUSTOM 任务在线检查**：每次轮询检查创建者是否在线，不在线则自动取消

## v1.4.3 - 多步骤任务错误保障、二次分析架构升级、Bukkit API 扩展与回复体验优化、AFK 挂机任务系统

### ✨ 新增功能
- 多步骤任务错误保障机制：即使部分步骤失败，也不会中断整个流程
- AnalysisSummary 统一摘要对象：单意图和多步骤任务共享同一结构化格式，便于 LLM 理解和关键词提取
- 统一 LLM 二次分析流程：所有技能执行结果（包括单意图）都经过 LLM 二次分析，回复更自然、能关联上下文
- **AFK 挂机任务系统**：支持 11 个事件监听器的后台监控任务
  - 玩家动态：上线/下线/死亡/传送/等级变化/切换世界
  - 生活行为：进入床/离开床/重生/物品损坏
  - 环境变化：天气变化
  - 双模式：纯通知（直接提醒）+ 回调（自动执行多步骤任务）
  - 自动管理：玩家下线自动取消，任务完成自动清理
  - 命令集成：`/kilacraft afk`（查询）、`/kilacraft afk cancel`（取消）
- 内置词汇表加载：从 JAR 包的 internal/vocabulary/ 目录加载词汇文件
- 三层关键词提取策略：原始查询 + 分词结果 + TF-IDF 关键词，兼容短文本和长文档
- 单字查询优化：支持“弓”、“剑”等单字物品名查询，通过自定义词典和停用词检查
- 结构化结果输出：步骤执行状态标记 [SUCCESS]/[FAILURE]/[SKIPPED]，便于 LLM 二次分析
- AI 回复 Markdown 自动转换：LLM 输出的 Markdown 格式（**加粗**、*斜体*、`代码`）自动转换为 Minecraft 颜色代码
- 连续对话规则增强：新增【实时数据重新获取规则】和【多步骤任务重复规则】，解决代词指代和多步骤截断问题
- **Bukkit API 扩展**：新增 21 个 API，总数达到 58 个（玩家 31 个、世界 20 个、服务器 6 个）
- **多步骤数据传递增强**：API 返回值自动提取到 dataMap，支持后续步骤通过 `{step_x.field}` 引用
- 盔甲装备查询：获取玩家全套盔甲（头盔、胸甲、护腿、靴子），支持多步骤数据传递
- 药水效果查询：查询当前所有药水效果（类型、等级、持续时间）
- 目标方块查询：获取玩家视线指向的方块信息
- 移动状态检测：蹲下/奔跑状态实时查询
- 客户端信息查询：玩家语言设置、显示名称
- 重生点查询：床/重生锚重生位置
- 总经验值查询：累计经验值查询
- 世界详情查询：生物群系、温度、湿度、海平面、实体统计、袭击事件、天气持续时间、世界时间详情

### 🔧 优化改进
- 插件入口类重构：onEnable() 从平铺代码提取为 6 个语义清晰的私有方法，严格保持初始化顺序
- 知识库关键词提取降噪：精准提取用户输入 + 执行结果数据，去除 step_id、状态标签、颜色代码、行首连字符等结构性噪音
