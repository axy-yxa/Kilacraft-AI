# Kilacraft-AI - 玩家画像与社交关系系统详解

> **最后更新**: 2026-05-06  
> **说明**: 本文档详细介绍 Kilacraft-AI v2.0.0 引入的玩家画像系统、社交关系图谱和服务器事件采集系统

---

## 📖 概述

v2.0.0 引入了三大数据驱动子系统，让 AI 记住每个玩家的行为偏好、追踪玩家间的社交关系，并自动记录服务器里程碑事件。这些系统共享数据库持久化层，协同工作让 AI 越来越懂你的玩家。

---

## 🧠 玩家画像系统

### 核心设计

玩家画像是 AI 对玩家的"长期记忆"。系统在玩家登录/退出时自动触发 LLM 分析，生成结构化的五点画像，并在后续对话中动态注入系统提示词，让 AI 的服务更个性化。

### 画像维度（五点法）

| 维度 | 说明 | 示例 |
|------|------|------|
| 游戏风格 | 玩家的玩法偏好 | PVP 狂热者 / 建筑大师 / 红石工程师 |
| 性格特征 | 行为模式 | 冒险型 / 社交型 / 谨慎型 |
| 内容偏好 | 感兴趣的话题 | 经济交易 / 副本攻略 / 装备打造 |
| 沟通风格 | 交流方式 | 喜欢简洁直接 / 喜欢详细解释 / 喜欢幽默 |
| 特别观察 | LLM 自由观察 | "该玩家最近对附魔系统特别感兴趣" |

### 工作流程

```
玩家登录 → 加载内存缓存 → 检查是否需要分析（三重门控）
                              ↓ 是
                         LLM 画像分析
                              ↓
                         更新内存缓存 + 异步写入 DB
                              ↓
                         下次对话时画像摘要注入系统提示词
```

### 三重门控机制

为防止不必要的 LLM 开销，画像分析需要**三者同时满足**才触发：

1. **时间间隔**：距上次分析 ≥ 设定时间（如 30 分钟）
2. **消息数量**：玩家累计发言数增加 ≥ 设定阈值（如 20 条）
3. **滑动窗口**：最近窗口内（如前 100 条消息）有足够新内容

### 版本戳防竞态

画像更新采用版本戳机制——写入 DB 时检查 `version_stamp`，只有版本号匹配才允许覆盖，防止并发更新导致数据丢失。

### 内存缓存

画像数据在内存中缓存，秒级响应。写入异步进行，不影响玩家体验。

## 🕸️ 社交关系图谱

### 核心设计

社交关系图谱追踪玩家间的互动，自动计算关系强度，形成动态社交网络。每日自动衰减弱化不活跃的关系。

### 交互权重

| 交互来源 | 权重 | 触发方式 |
|----------|:---:|----------|
| 私聊（/tell、/msg） | +0.01 | 自动监听聊天事件 |
| TPA 传送 | +0.02 | 自动监听 CMI TPA 命令 |
| Skill 交互（白名单） | +0.005 | SocialRelationExtractor 定期扫描 kca_skill_log |

### 每日衰减

```
新强度 = 当前强度 × 0.95（每日衰减 5%）
```

衰减后强度 < 阈值（如 0.01）的关系自动清理，保持数据新鲜度。

### 分布式安全机制

#### 问题
多子服环境下，多个服务器可能同时执行每日衰减，导致重复衰减。

#### 解决方案
- **水位标记表**（kca_watermark）：每个周期性任务一条记录
- **DB 行锁**（`SELECT FOR UPDATE`）：开始衰减前加锁，检查 `last_run_date` 是否为今天
- **CAS 互斥**（TaskScheduler 层）：单服内同一任务同一时间只有一个线程执行

两层互斥保护确保多子服环境不冲突。

### 社交关系提取器

`SocialRelationExtractor` 定期扫描 `kca_skill_log` 表，查找白名单 Skill 中涉及"玩家-玩家"互动的记录（如传送、交易等），自动增强对应玩家间的社交关系。

**白名单 Skill 示例**：
- `cmi.send_tp_request`（TPA 传送请求）
- `command.execute_command` 中的 `/tpa` 类命令

### 对话中的社交感知

AI 问候语可引用社交关系：
> "欢迎回来！你的好友 Steve 也在线。你们最近交流很频繁呢。"

## 📡 服务器事件采集系统

### 核心设计

自动记录服务器中发生的里程碑事件，让玩家离线后也能回顾"错过了什么"。

### 事件类型

| 事件类型 | 触发条件 | 记录内容 |
|----------|---------|---------|
| `PLAYER_DEATH` | 玩家死亡 | 死亡位置、死亡原因 |
| `PLAYER_ADVANCEMENT` | 玩家解锁成就 | 成就名称、描述 |
| `PLAYER_LEVELUP` | 玩家升级 | 新等级 |
| `MARKET_LIST` | 玩家上架商品 | 商品名、价格、数量 |
| `MARKET_SELL` | 商品售出 | 商品名、价格、买家 |
| `MARKET_BUY_RECEIVE` | 收到购买款项 | 商品名、金额、卖家 |

### 离线事件聚合器

玩家上线时，系统采用三大分类架构查询离线期间发生的事件，生成摘要供 AI 问候语使用：

```
玩家: [登录]
系统: 三大分类数据聚合
  → 分类一（自己）：你的钻石已售出（+$500）
  → 分类二（好友）：Steve 达成了 2 个成就，Alex 升了 3 级
  → 分类三（摘要）：累计登录 100 次里程碑！上次游玩击败了末影龙
  → 使用这些信息生成登录问候语
```

事件数量和类型可通过 `greeting.yml` 配置，好友动态通过 LEFT JOIN `kca_player_profile` 获取玩家名。

## 🔧 配置参考

### 画像分析控制（llm.yml）

```yaml
agent:
  profile:
    enabled: true
    min_interval_minutes: 30          # 最小分析间隔（分钟）
    min_message_delta: 20             # 最小新增消息数
    sliding_window_size: 100          # 滑动窗口大小
```

### 社交关系配置（内部参数）

社交关系权重和衰减率目前由代码内部控制，未来版本可能开放 YAML 配置。当前默认值：
- 私聊权重：0.01
- TPA 权重：0.02
- Skill 交互权重：0.005
- 日衰减率：5%
- 弱关系清理阈值：0.01

### 问候与离线事件（greeting.yml）

```yaml
greeting:
  enabled: true
  max_own_offline_events: 10     # 玩家自己离线事件最大条数（分类一）
  max_friend_offline_events: 5   # 好友动态最大条数（分类二）
  max_summary_events: 3          # 上次游玩亮点最大条数（分类三）
  greeting_cooldown_minutes: 30
```
